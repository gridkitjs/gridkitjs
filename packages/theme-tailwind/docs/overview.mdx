@gridkitjs/react renders semantic class names (`gridkit-data-grid`, `gridkit-header-cell`, `gridkit-grid-row`) and this stylesheet targets them directly. Nothing needs to scan component source, and every colour, size and line is a CSS custom property, so overriding one is plain CSS.

## Requirements

The stylesheet is written for Tailwind CSS v4 and needs `tailwindcss` 4.3.3 or later, a peer dependency. It is not plain CSS: it uses Tailwind's `@variant dark` to follow your app's dark mode and `@theme inline` to register the palette as colour utilities (`text-gridkit-accent`, `bg-gridkit-surface`), so your app's Tailwind build has to compile it. Tailwind v3 cannot.

## Install

<PackageInstall pkg="@gridkitjs/theme-tailwind" />

Import it in your app's CSS entry, after Tailwind itself:

```css title="src/index.css"
@import "tailwindcss";
@import "@gridkitjs/theme-tailwind/styles.css";
```

The [quick start](/docs/react) walks through the whole setup, Tailwind included, in a new Vite app.

## Without Tailwind

Without Tailwind, install [`@gridkitjs/theme-css`](/docs/theme-css) instead: this stylesheet as plain CSS, generated from it, with the same rules, tokens and class names. Its dark mode follows the system's colour scheme, and `.gridkit-light` and `.gridkit-dark` override it.

## Class names

The stylesheet targets the class names `@gridkitjs/react` renders and nothing else. Every one starts with `gridkit-`, so no rule reaches an element outside the grid; a state is an `is-*` class beside one of them, such as `.gridkit-grid-row.is-selected`. [Class names](/docs/theme-tailwind/class-names) lists every class, state class and `data-gridkit-*` attribute, grouped by part of the grid, with what each one marks.

The grid is a set of siblings rather than one table, so the header and footer never scroll with the rows: `div.gridkit-data-grid-viewport` is the root, and each of the header's, rows' and footer's tables is a `.gridkit-data-grid`.

## Overlays and menus

The grid's menus, column chooser and filter menu render into `document.body`, each in a `.gridkit-overlay`, so no scrolling ancestor clips them.

Because an overlay sits outside the grid, it takes its colours from the tokens on `:root` — or from `.gridkit-light`/`.gridkit-dark`, which the grid copies onto it from the nearest ancestor that has one (below). A token you override on some other wrapper around the grid does not reach its menus or its column chooser; override it on `:root`, or on `.gridkit-overlay` as well.

## Scrollbars

The viewport, the row area, the menus, the column chooser list and the filter checklist show thin scrollbars (`scrollbar-width: thin`) whose thumb is `--gridkit-scrollbar-thumb`, by default `--gridkit-fg-muted` at 45%, on a transparent track, so they follow light and dark with the other tokens. Engines without `scrollbar-color` get an 8px rounded `::-webkit-scrollbar` equivalent. Only the grid's own elements are styled, never `html` or `body`. To recolour the thumb, override the token's light and dark pair; to change the rest, set `scrollbar-width` or `scrollbar-color` on any of those classes.

## Printing

An `@media print` block makes the browser's own print of the page — <Kbd>Ctrl</Kbd>+<Kbd>P</Kbd>, or <Kbd>Cmd</Kbd>+<Kbd>P</Kbd> on a Mac — read as a plain table. Inside `.gridkit-data-grid-viewport`, it:

- hides the toolbar, the group-by bar, the built-in pager and the resize handles;
- drops a `height` bound and the inner scrolling, so every row the grid has drawn flows onto as many pages as it takes;
- drops the focus ring;
- prints the header's and selected rows' shading as it is (`print-color-adjust: exact`) rather than dropping it to save ink;
- keeps each row whole rather than splitting it across two pages.

It prints only what the grid has drawn: not the rows on another page, nor those a virtualized grid has not mounted. The grid's own [Print](/docs/react/printing) is the supported way to print every row. It prints a separate document in a hidden frame, which sees none of the page's CSS — this stylesheet included — and carries a print stylesheet of its own; restyle it through the `print` option's `styles`, not here.

## Theme tokens

Every colour, size and line the stylesheet draws comes from a theme token, a `--gridkit-*` custom property declared on `:root`. To change one, override it on `:root`, in CSS after the theme's import; a colour is overridden by its light and dark pair. [Theme tokens](/docs/theme-tailwind/tokens) lists every token with its default, and explains how overrides reach the grid. [Presets](/docs/theme-tailwind/presets) are ready-made sets of them, imported after the theme.

```css
:root {
  --gridkit-spacing: 0.1875rem;
  --gridkit-accent-light: oklch(0.6 0.17 145);
  --gridkit-accent-dark: oklch(0.7 0.15 145);
}
```

### Colour utilities

Each colour token is also a Tailwind colour named after it with a `gridkit-` prefix, so it works with any colour utility: `bg-gridkit-surface`, `text-gridkit-fg-muted`, `border-gridkit-line`, `ring-gridkit-accent`. The palette's nine are `gridkit-surface`, `gridkit-surface-muted`, `gridkit-line`, `gridkit-hover-line`, `gridkit-fg`, `gridkit-fg-muted`, `gridkit-accent`, `gridkit-selected` and `gridkit-selected-strong`, and each colour that tunes one part of the grid is registered the same way, such as `gridkit-header-bg` or `gridkit-focus-ring`. The prefix keeps them from colliding with an `accent` or `surface` colour in your app's own theme. A utility reads the live token on the element it sits on, so it follows light and dark mode, `.gridkit-light` and `.gridkit-dark`, and any override of the token.

### Light and dark values

Each colour token is backed by a raw pair, `--gridkit-<name>-light` and `--gridkit-<name>-dark` (`--gridkit-accent-light`, `--gridkit-accent-dark` and so on), defined once on `:root`. The rules only ever read the live `--gridkit-<name>`, and the stylesheet points it at one side of the pair: the light one on `:root`, the dark one under `@variant dark`, and whichever `.gridkit-light` or `.gridkit-dark` names on an element that has one. A colour that sets one part defaults to a palette colour's pair, as `--gridkit-header-bg-light` is `var(--gridkit-surface-light)`, so it follows an override of that pair.

So an override of the live `--gridkit-<name>` on `:root` falls short twice. A grid pinned with `.gridkit-light`/`.gridkit-dark`, and its menus, keep the pair's value, since the class sets `--gridkit-<name>` again, closer to the grid; and the colours that default to it keep theirs, since they read its pair. To change a colour everywhere, override the raw pair instead:

```css
:root {
  --gridkit-accent-light: oklch(0.6 0.17 145);
  --gridkit-accent-dark: oklch(0.7 0.15 145);
}
```

## Dark mode

GridKit doesn't register its own `dark:` variant — it follows whatever your app's Tailwind build already resolves `dark:` to. Out of the box that's the OS preference. For the common class-toggle pattern, declare it yourself, same as any Tailwind v4 app would:

```css
@import "tailwindcss";
@custom-variant dark (&:where(.dark, .dark *));
@import "@gridkitjs/theme-tailwind/styles.css";
```

```ts
document.documentElement.classList.toggle("dark", isDark);
```

A colour's dark value is the `-dark` side of its pair, which the grid reads wherever `dark:` applies, so a theme sets that rather than redefining the token inside `@variant dark { }`; see [light and dark values](#light-and-dark-values).

## Forcing a theme on one grid

`.gridkit-light` / `.gridkit-dark` pin a grid to one palette regardless of the ambient `dark:` state. Put either on any ancestor of the grid, including the grid's own root; its menus follow, since the grid copies the class onto each overlay it opens. Toggle the app theme below and only the first grid follows it:

```tsx
<div className="gridkit-dark">
  <DataGrid ... />
</div>
```
