@gridkitjs/react renders semantic class names — gridkit-data-grid, header-cell, grid-row — and this stylesheet targets them directly. Nothing needs to scan component source, and every colour is a CSS custom property, so overriding one is plain CSS.

## Install

```bash
npm install @gridkitjs/theme-tailwind
```

```css
@import "tailwindcss";
@import "@gridkitjs/theme-tailwind/styles.css";
```

## Layout

The grid is a set of siblings rather than one table, so the header and footer never scroll with the rows:

| Class                         | Element   | Description                                                                                                                                                       |
| ----------------------------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.gridkit-data-grid-viewport` | `<div>`   | The grid's root: the toolbar, the group-by bar, the tables and the pager, in that order. Scrolls sideways when the columns are wider than it.                     |
| `.gridkit-data-grid-tables`   | `<div>`   | Holds the three tables and carries `role="grid"` (or `"treegrid"` while grouped), since the pattern needs one element around every row.                           |
| `.gridkit-data-grid-header`   | `<table>` | The header's table. Also a `.gridkit-data-grid`.                                                                                                                  |
| `.gridkit-data-grid-body`     | `<div>`   | The scroll container around the rows' table — the one `height` bounds, through `--gridkit-body-height`.                                                           |
| `.gridkit-data-grid-footer`   | `<table>` | The grand-total footer's table, while `aggregates` is non-empty. Also a `.gridkit-data-grid`.                                                                     |
| `.gridkit-sr-only`            | `<div>`   | The live region announcements are read from, clipped to nothing but left in the accessibility tree. Usable on anything of your own that should be read, not seen. |

## Toolbar

The grid's [toolbar](/docs/react/toolbar) is the first thing inside it, above the group-by bar. It sticks to the grid's start edge, so it stays in view while the tables scroll sideways, and keeps its entries on one row — what does not fit moves into "More". States are ARIA attributes, not classes.

| Class                       | Element    | Description                                                                                                                                                                                  |
| --------------------------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.gridkit-toolbar`          | `<div>`    | The toolbar (`role="toolbar"`): its row, padding, surface and bottom border.                                                                                                                 |
| `.toolbar-button`           | `<button>` | A command's button, a dropdown, or "More". `[aria-disabled="true"]` mutes it, `[aria-pressed="true"]` marks a toggle that is on, and `[aria-expanded="true"]` a dropdown whose menu is open. |
| `.toolbar-button-icon`      | `<span>`   | The icon before a button's label; hidden when empty.                                                                                                                                         |
| `.toolbar-button-indicator` | `<span>`   | The chevron after a dropdown's label.                                                                                                                                                        |
| `.toolbar-more`             | `<button>` | The "More" button, holding the entries that do not fit. Also a `.toolbar-button`. Sticks to the toolbar's end edge when the search box and custom entries alone overflow it.                 |
| `.toolbar-search`           | `<input>`  | The search box: `12rem`, or half the toolbar's width when that is less.                                                                                                                      |
| `.toolbar-separator`        | `<div>`    | A separator (`role="separator"`).                                                                                                                                                            |
| `.toolbar-spacer`           | `<div>`    | The free space, pushing what follows it to the far end.                                                                                                                                      |
| `.toolbar-custom`           | `<div>`    | Holds what `renderToolbarItem` draws.                                                                                                                                                        |

A dropdown's menu, and "More"'s, are [menus](#overlays-and-menus) like the context menu's.

## Overlays and menus

The grid's [context menu](/docs/react/context-menu) renders into `document.body`, not inside the grid, so no scrolling ancestor clips it — its selectors are top-level rather than under `.gridkit-data-grid`. States are ARIA attributes, not classes.

| Class                     | Element  | Description                                                                                                                                                                                 |
| ------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.gridkit-overlay`        | `<div>`  | The positioned box around every menu, submenu and panel, `position: fixed` and above the grid. Carries the grid's `.gridkit-light`/`.gridkit-dark`.                                         |
| `.gridkit-menu`           | `<div>`  | A menu (`role="menu"`): its surface, border, shadow and padding.                                                                                                                            |
| `.menu-item`              | `<div>`  | An item. Focused (`:focus`) when the keyboard or the pointer is on it; `[aria-disabled="true"]`, `[aria-checked="true"]` and `[aria-expanded="true"]` (its submenu is open) style the rest. |
| `.menu-item-icon`         | `<span>` | The icon before the label — empty when the item has none, so labels line up; a checked item's check.                                                                                        |
| `.menu-item-label`        | `<span>` | The label.                                                                                                                                                                                  |
| `.menu-item-shortcut`     | `<span>` | A key-combination hint after the label.                                                                                                                                                     |
| `.menu-submenu-indicator` | `<span>` | The chevron on an item that opens a submenu.                                                                                                                                                |
| `.menu-separator`         | `<div>`  | A separator (`role="separator"`).                                                                                                                                                           |

Because an overlay sits outside the grid, it takes its colours from the tokens on `:root` — or from `.gridkit-light`/`.gridkit-dark`, which the grid copies onto it from the nearest ancestor that has one (below). A token you override on some other wrapper around the grid does not reach its menus or its column chooser; override it on `:root`, or on `.gridkit-overlay` as well.

## Printing

An `@media print` block makes the browser's own print of the page — <Kbd>Ctrl</Kbd>+<Kbd>P</Kbd>, or <Kbd>Cmd</Kbd>+<Kbd>P</Kbd> on a Mac — read as a plain table. Inside `.gridkit-data-grid-viewport`, it:

- hides the toolbar, the group-by bar, the built-in pager and the resize handles;
- drops a `height` bound and the inner scrolling, so every row the grid has drawn flows onto as many pages as it takes;
- drops the focus ring;
- prints the header's and selected rows' shading as it is (`print-color-adjust: exact`) rather than dropping it to save ink;
- keeps each row whole rather than splitting it across two pages.

It prints only what the grid has drawn: not the rows on another page, nor those a virtualized grid has not mounted. The grid's own [Print](/docs/react/printing) is the supported way to print every row. It prints a separate document in a hidden frame, which sees none of the page's CSS — this stylesheet included — and carries a print stylesheet of its own; restyle it through the `print` option's `styles`, not here.

```css
  --gridkit-accent: oklch(0.6 0.17 145);

}
```

### Light and dark values

Each token is backed by a raw pair, `--gridkit-<name>-light` and `--gridkit-<name>-dark` — `--gridkit-accent-light`, `--gridkit-accent-dark` and so on — defined once on `:root`. The stylesheet only ever reads `--gridkit-<name>`, and points it at one of the pair: the light one on `:root`, the dark one under `@variant dark`, and whichever `.gridkit-light` or `.gridkit-dark` names on an element that has one.

That reassignment is why an override of `--gridkit-<name>` on `:root` does not reach a grid, or its menus, pinned with `.gridkit-light`/`.gridkit-dark`: the class sets `--gridkit-<name>` again, closer to the grid. To change a colour everywhere, override the raw pair instead:

```css
:root {
  --gridkit-accent-light: oklch(0.6 0.17 145);
  --gridkit-accent-dark: oklch(0.7 0.15 145);
}
```

## Dark mode

GridKit doesn't register its own `dark:` variant — it follows whatever your app's Tailwind build already resolves `dark:` to. Out of the box that's the OS preference. For the common class-toggle pattern, declare it yourself, same as any Tailwind v4 app would:

```css
@import "tailwindcss";
@custom-variant dark (&:where(.dark, .dark *));
@import "@gridkitjs/theme-tailwind/styles.css";
```

```ts
document.documentElement.classList.toggle("dark", isDark);
```

Redefine a token inside `@variant dark { }` to change its dark value too:

```css
:root {
  --gridkit-accent: oklch(0.6 0.17 145);

  @variant dark {
    --gridkit-accent: oklch(0.7 0.15 145);
  }
}
```

## Forcing a theme on one grid

`.gridkit-light` / `.gridkit-dark` pin a grid to one palette regardless of the ambient `dark:` state. Put either on any ancestor of the grid, including the grid's own root; its menus follow, since the grid copies the class onto each overlay it opens.
