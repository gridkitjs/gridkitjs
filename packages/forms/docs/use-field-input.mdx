---
title: "useFieldInput"
description: "The hook every forms input is built on: binds a native text control to a field's value, events, validation and hidden input."
---

`useFieldInput(props, kind, options)` binds a native `<input>` or `<textarea>` to a field: the value and the text being typed, the [events](/docs/forms/events) in their order, controlled and imperative changes, validation, and a hidden input that submits the value under `name`. It renders nothing itself: spread `controlProps` on the control and draw `hiddenInput` beside it. `kind` says how the input reads, writes and submits its value, and `options` how it behaves.

<Callout type="note" title="First iteration">
  This hook is a first iteration and may change before the first release.
</Callout>

## When to use it

To build an input of your own that behaves like the forms inputs, which are built on it. The control's text belongs to the field, never to React, so the control is uncontrolled: it gets `defaultValue`, and the field writes its text while keeping the caret where the user left it.

## Example

```tsx title="App.tsx"
import { useRef } from "react";
import {
  formatText,
  textParser,
  useFieldInput,
  type FieldInputKind,
  type InputHandle,
} from "@gridkitjs/forms";

const text: FieldInputKind<string> = {
  defaultParse: textParser({ trim: true }),
  defaultFormat: formatText,
  serialize: (value) => value,
};

export function App() {
  const handle = useRef<InputHandle<string>>(null);
  const field = useFieldInput(
    {
      name: "name",
      defaultValue: "Ada",
      validate: (value) => (value === null ? "Enter your name" : null),
      handleRef: handle,
    },
    text,
  );
  return (
    <form>
      <label htmlFor={field.controlProps.id}>Name</label>
      <input {...field.controlProps} />
      {field.hiddenInput}
      {field.messages.map((message) => (
        <p key={message.text}>{message.text}</p>
      ))}
      <button type="button" onClick={() => handle.current?.reset()}>
        Reset
      </button>
    </form>
  );
}
```

## Props

| Prop                   | Type                                           | Default   | Description                                                                                     |
| ---------------------- | ---------------------------------------------- | --------- | ----------------------------------------------------------------------------------------------- |
| `value`                | `V \| null`                                    |           | Present, `null` included, means controlled.                                                     |
| `defaultValue`         | `V \| null`                                    | `null`    | The starting value of an uncontrolled field, and what `reset` returns to.                       |
| `parse`, `format`      | `Parser<V>`, `Formatter<V>`                    |           | The app's reading and writing; the context holds the input's own, to wrap.                      |
| `validate`             | `Validator<V> \| Validator<V>[]`               |           | Checks the value after every change; a returned string is an error.                             |
| `required`             | `boolean`                                      | `false`   | Sets `aria-required` and stars the label of the `Field` around it. Add the check to `validate`. |
| `message`              | `FieldMessageInput \| FieldMessageInput[]`     |           | Your messages, always shown with the field's own; a string is an error.                         |
| `invalid`              | `boolean`                                      | `false`   | The error state with no message, for a form library that shows its errors elsewhere.            |
| `onClear`              | `(event: FieldClearEvent<V>) => void`          |           | Called first when the input's `clear` runs, with `previousValue` and `previousText`.            |
| `name`                 | `string`                                       |           | Submits the value through a hidden input. The visible control never has a `name`.               |
| `form`                 | `string`                                       |           | The `id` of a `<form>` elsewhere that the value belongs to.                                     |
| `readOnly`, `disabled` | `boolean`                                      |           | Passed to the control; `disabled` disables the hidden input too, so nothing is submitted.       |
| `mode`                 | `"edit" \| "display"`                          |           | `"display"` shows the value as text; a `Field` or form around the input sets it otherwise.      |
| `id`                   | `string`                                       | generated | The control's `id` outside a [`Field`](/docs/forms/field); inside one, the field's.             |
| `locale`               | `Intl.LocalesArgument`                         |           | For parsing, formatting and messages.                                                           |
| `messages`             | `Partial<FormsMessages>`                       |           | Strings laid over the English defaults.                                                         |
| `ref`                  | `Ref<HTMLInputElement \| HTMLTextAreaElement>` |           | The native control.                                                                             |
| `handleRef`            | `Ref<InputHandle<V>>`                          |           | The handle below.                                                                               |
| `onFocus` ... `onBlur` | handlers                                       |           | The nine [events](/docs/forms/events).                                                          |

`kind` is a `FieldInputKind<V, D>`: `defaultParse` and `defaultFormat` (the input's own reading and writing, which `parse` and `format` can wrap) and `serialize` (the value as its hidden input submits it, the same in every locale; `null` submits `""`). `textParser` and `formatText` are a text input's. Three members are optional: `equals` (whether two values are one, `Object.is` by default: a decimal input compares exactly), `details` (the input's own details `D`, added to every event it fires, as a number input adds `NumberDetails`) and `filterInput` (the input's judgement of each edit the app's `onBeforeInput` lets through: refuse it, rewrite it, or replace the whole text and place the caret).

`options` is a `FieldInputOptions`, the input's own behaviour, which the latest render passes on:

| Option           | Type                                        | Default               | Description                                                                                                                                                                    |
| ---------------- | ------------------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `startAdornment` | `boolean`                                   | `false`               | Something sits at the control's start, so a floating label stays raised.                                                                                                       |
| `changeDelay`    | `number`                                    | `0`                   | Milliseconds typing must pause before the text is read, for a search box.                                                                                                      |
| `selectOnFocus`  | `boolean`                                   | `false`               | Selects all the text on focus from the keyboard or from code.                                                                                                                  |
| `escape`         | `"revert" \| "clear" \| "none"`             | `"revert"`            | What <Kbd>Escape</Kbd> does: puts back the last commit, clears the field (after `onClear`), or nothing.                                                                        |
| `mapCaret`       | `(previousText, caret, nextText) => number` | distance from the end | Where the caret goes when the field's text is written into the focused control.                                                                                                |
| `decimalKey`     | `string`                                    |                       | What the keypad's decimal key types, whatever the keyboard layout.                                                                                                             |
| `lastCaret`      | `(text) => number`                          |                       | The furthest a click may leave the caret: a mask's first empty slot.                                                                                                           |
| `toggle`         | `{ threeState?: boolean }`                  |                       | The control is a checkbox, flipped whole: forms-dom's [toggle behaviour](/docs/forms-dom/toggles) drives it, every flip commits, and a `Field`'s floating label sits above it. |

## What it returns

| Field                  | Description                                                                                                                                                                                     |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `controlProps`         | `ref`, `id`, `defaultValue` (a toggle: `defaultChecked`), `readOnly` (a toggle: `aria-readonly`), `disabled`, `aria-invalid`, `aria-describedby` and `aria-required`, to spread on the control. |
| `mode`, `displayValue` | The mode in effect, and the value as text to draw in place of the control in display mode.                                                                                                      |
| `hiddenInput`          | `<input type="hidden">` carrying `name`, or `null` without one.                                                                                                                                 |
| `messages`             | The messages to show: your `message`, and the field's own from the first commit attempt or `revealMessages()` on, live as the user types.                                                       |
| `severity`             | The most serious message shown, under the input or in the `Field` around it, or `"error"` for `invalid`: the box's border colour.                                                               |
| `clear(nativeEvent)`   | Fires `onClear`, then empties the field and commits it, with `source` and `trigger` `"clear"`: a clear button's action.                                                                         |
| `getValue()`           | The value at the moment of the call, for a handler outside React's render.                                                                                                                      |
| `change(value, cause)` | The change chain to `value`, with `cause`'s `source` and native event, and no commit: a step, a part of a composite input.                                                                      |
| `text`, `state`        | The text on screen, and the whole field state (`value`, `draft`, `phase`, ...).                                                                                                                 |

## Behaviour

- **Inside a [`Field`](/docs/forms/field)** the control takes the field's `id`, description, and required and invalid states, `readOnly`, `disabled` and `mode` set on the field or the form win, and the field lists the input's messages and floats its label from the control's focus and text. Draw the messages yourself only outside a field.
- **Disabled.** A disabled field is not validated: it shows none of its own messages.
- **Validity.** The control's custom validity holds the field's first error from the start, shown or not, so a plain `<form>` refuses to submit while the field holds one.
- **Server rendering.** The control's text and the hidden input's value render on the server, and hydrate without a mismatch.
- **`StrictMode`** mounts the field twice in development; each event still fires once.

## The handle

`handleRef` gives an `InputHandle<V>`:

| Member                     | Description                                                                    |
| -------------------------- | ------------------------------------------------------------------------------ |
| `element`                  | The control, while it is in the page.                                          |
| `focus(options)`, `blur()` | Moves focus.                                                                   |
| `getValue()`, `getText()`  | The value and the text on screen.                                              |
| `setValue(value)`          | `onBeforeChange`, `onChange` and `onValidate` with `source: "api"`; no commit. |
| `reset()`                  | Back to `defaultValue`, or `null`, the same way.                               |
| `revealMessages()`         | Shows the field's messages from now on, as a commit attempt would.             |
