---
title: "Checkbox"
description: "Checkbox: a native checkbox whose value is true, false or null (indeterminate), with an optional three-state cycle and the forms events."
---

`Checkbox` is a native `<input type="checkbox">` whose value is `true`, `false` or `null`, drawn indeterminate ("mixed"). `label` is the text beside the box, `labelPlacement` puts it after or before, and `threeState` lets a flip set `null`. Every flip fires the same [events](/docs/forms/events) as a text input, then commits at once.

<Callout type="note" title="First iteration">
  This component is a first iteration and may change before the first release.
</Callout>

## When to use it

For a yes-or-no answer the user confirms with the rest of a form: agreeing to terms, opting in. For a setting that takes effect the moment it changes, use a [`Switch`](/docs/forms/switch). For a "select all" over a partial selection, set `value={null}`.

## Example

```tsx title="App.tsx"
import { Checkbox, Field, Form } from "@gridkitjs/forms";

export function App() {
  return (
    <Form
      aria-label="Sign up"
      onSubmit={(event) => {
        event.preventDefault();
        console.log([...new FormData(event.currentTarget)]);
      }}
    >
      <Field label="Newsletter" description="One email a month">
        <Checkbox name="newsletter" label="Send me the newsletter" />
      </Field>
      <Checkbox name="terms" label="I agree to the terms" required />
      <button type="submit">Sign up</button>
    </Form>
  );
}
```

## Props

Every prop [`TextInput`](/docs/forms/text-input#props) takes that means something for a toggle: `value`, `defaultValue`, the events, `validate`, `required`, `message`, `invalid`, `mode`, `readOnly`, `disabled`, `density`, `id`, `name`, `form`, `autoFocus`, `description`, the `aria-*` props, `locale`, `messages`, `className`, `style` and `handleRef`. These differ:

| Prop             | Type                    | Default | Description                                                                                                       |
| ---------------- | ----------------------- | ------- | ----------------------------------------------------------------------------------------------------------------- |
| `defaultValue`   | `boolean \| null`       | `false` | `null` starts it indeterminate.                                                                                   |
| `label`          | `ReactNode`             |         | The text beside the box. It names the control, with the label of a `Field` around it, and a press on it flips it. |
| `labelPlacement` | `"end" \| "start"`      | `"end"` | The label after the box or before it, in reading order.                                                           |
| `threeState`     | `boolean`               | `false` | A flip can set `null`: unchecked, checked, mixed, unchecked.                                                      |
| `required`       | `boolean`               | `false` | It must be checked: "Check this box to continue" until it is.                                                     |
| `ref`            | `Ref<HTMLInputElement>` |         | The native checkbox.                                                                                              |

## Behaviour

- **The cycle.** Without `threeState`, unchecked and mixed both go to checked, and checked to unchecked: an app's `null` checks on the first flip. With it, unchecked goes to checked, checked to mixed, mixed to unchecked.
- **Submitting.** With `name`, a hidden input submits `"true"`, `"false"`, or `""` while mixed, so an unchecked box is still sent. The checkbox itself has no `name`.
- **Read-only.** `readOnly` refuses every flip; the box stays focusable and is read as read-only.
- **Display mode.** "Yes", "No", or a dash read as "No value" for `null`, beside the label.
- **In a `Field`.** The field's label stays above the box in every position but `start` and `hidden`: a floating label has nowhere to rest, so it sits as `top` does.

## Events

A flip fires `onBeforeChange`, `onChange`, `onValidate`, `onBeforeCommit` and `onCommit`, each with `source` (and `trigger`) `"toggle"` and `text` "Yes", "No" or `""`. `nativeEvent` is the `click` for a press, or the Space `keydown` for a flip by <Kbd>Space</Kbd>. `onFocus` and `onBlur` fire as for a text input; leaving commits nothing more. A flip `onBeforeChange` prevents leaves the box as it was.

## Keyboard and pointer

| Key              | Does                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| <Kbd>Space</Kbd> | Flips it through the cycle; held down, it flips once.                   |
| <Kbd>Tab</Kbd>   | Moves on.                                                               |
| <Kbd>Enter</Kbd> | Nothing of its own; in a `Form` with `enterMovesToNextField`, moves on. |

A press anywhere on the row, the label included, flips it. Under a coarse pointer the row is at least 24px in both directions.

## Messages and localization

From `FormsMessages`: `displayChecked` ("Yes"), `displayUnchecked` ("No"), `requiredChecked` ("Check this box to continue") and `emptyValue` ("No value").
