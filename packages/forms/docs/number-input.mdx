---
title: "NumberInput"
description: "NumberInput: locale-aware number entry with exact decimals on request, fixed-decimal typing, a currency or unit beside the number, and stepping by keys and stepper buttons."
---

`NumberInput` is a number field whose value is a JS `number`, or with `valueType="decimal"` an exact decimal string (`"1234.50"`), `null` when empty. It reads and writes numbers the way the field's locale does, shows plain digits while it has focus and the number grouped once it leaves, steps by the arrow keys and optional stepper buttons, and fires the forms [events](/docs/forms/events) with the number's details on each.

<Callout type="note" title="First iteration">
  This component is a first iteration and may change before the first release.
</Callout>

## When to use it

For quantities, prices, amounts and rates people type. Put it in a [`Field`](/docs/forms/field) for its label, help text and messages. For a percentage use [`PercentInput`](/docs/forms/percent-input), which stores 12 % as 0.12 or as 12.

## Example

```tsx title="App.tsx"
import { Field, Form, NumberInput } from "@gridkitjs/forms";

export function App() {
  return (
    <Form locale="de-DE">
      <Field label="Quantity">
        <NumberInput name="quantity" integer min={0} stepper="end" />
      </Field>
      <Field label="Price">
        <NumberInput name="price" currency="EUR" min={0} />
      </Field>
      <Field label="Total" description="Exact to the cent">
        <NumberInput name="total" valueType="decimal" fractionDigits={2} />
      </Field>
      <button type="submit">Save</button>
    </Form>
  );
}
```

## Value types

The value is a `number`, or with `valueType="decimal"` a string in normal form with the minimum decimals (`"1234.50"`). Either way values are stepped, rounded and compared as exact decimals, so 0.1 stepped by 0.1 is 0.2, never 0.30000000000000004. As a `number`, text whose digits a number cannot keep ("9007199254740993") cannot be read and says so; use the decimal string for long amounts. The hidden input submits the value in the same form in every locale, `1234.5`.

## Typing

While the field has focus it shows plain digits and the decimal separator, `-1234,5` in `de-DE`; once it leaves, the number grouped and padded, `-1.234,50`, with a currency or unit drawn beside the box's text. Keys that cannot be part of a number are refused before they show: letters, `e`, currency and percent signs, a second decimal separator, a group separator where the grouping does not allow it. Pastes are cleaned: "$1,234.50" pasted into a `de-DE` field becomes `1234,50`. Text that still cannot be read ("1.5" in `de-DE`) stays as typed with its message, and the value stays the last one read. Extra decimals round, and the rounded text is written on commit.

The keypad's decimal key types the field's separator on any keyboard layout, so the keypad "." of a US keyboard types "," in a German field.

## Fixed decimals

With fixed decimals (`fractionDigits`, or a currency's minor units) the field types the way accounting fields do:

- The decimals show as soon as there is a value: typing 5 gives `5,00`, the caret before the separator.
- Digits go before the decimals; the decimal separator, or the keypad's decimal key, or either `.` or `,`, moves the caret to the first decimal and types nothing.
- Decimals are typed over and never grow: once the caret reaches the end, more digits are refused.
- Backspace turns a decimal to 0 and moves back; from the first decimal it deletes the last integer digit. <Kbd>Delete</Kbd> mirrors it. Deleting the last digit that counts, or selecting all and deleting, empties the field.
- A paste is rounded to the decimals, the caret at the end of its integer part.

`decimalEntry="free"` types them as any other field does.

## Stepping

| Key                                    | Does                                                         |
| -------------------------------------- | ------------------------------------------------------------ |
| <Kbd>↑</Kbd>, <Kbd>↓</Kbd>             | One step up or down, within `min` and `max`.                 |
| <Kbd>PageUp</Kbd>, <Kbd>PageDown</Kbd> | A large step.                                                |
| <Kbd>Home</Kbd>, <Kbd>End</Kbd>        | To `min` or `max` when it is set; otherwise the caret moves. |
| <Kbd>Enter</Kbd>                       | Commits.                                                     |
| <Kbd>Escape</Kbd>                      | Puts back the last committed value when the text differs.    |
| <Kbd>Tab</Kbd>                         | Commits, then focus moves on.                                |

From empty the first step sets 0 (or a limit that leaves 0 out); a value off the step grid goes to the grid first, as native number inputs do. A step fires `onStep`, then `onBeforeChange`, `onChange` and `onValidate` with `source: "step"`, and no commit: leaving commits. At a limit a step does nothing and fires nothing.

A stepper button steps once when pressed and repeats while held: after 400 ms, every 60 ms, and every 30 ms after 20 steps. The hold ends when it is let go, when the pointer leaves the button, when the field loses focus and at a limit. The buttons never take focus, and focus the field when it does not have it, so leaving commits. At a limit, and in a read-only field, they are drawn disabled.

## Events

Every event carries `NumberDetails`: `decimal` (the value as an exact decimal string, whatever the value type), `formatted` (the full text, "1.234,50 €") and `reading` (how the text on screen reads: the decimal separator taken, whether it grouped, the negative style, the digits typed, whether a paste was cleaned; `null` while it shows the value formatted). A typed trailing 0 after the decimal separator fires `onInput` but not `onChange`: the value is the same. In a fixed-decimal field, a digit typed over the same digit leaves the text as it was and fires nothing.

## Accessibility

The control is a native `<input type="text">` with `role="spinbutton"`, `aria-valuenow` (absent while empty), `aria-valuemin` and `aria-valuemax` when set, and `aria-valuetext` with the full text, so a screen reader says the currency. With `stepping="none"` it is a plain text box and the currency or unit is read as its description. Where the locale writes numbers left to right the control is `dir="ltr"`, so "-1234" keeps its minus on the left in a Hebrew field; in `ar-EG` it follows the field. VoiceOver on iOS changes a spinbutton by swipes that send no keys, so those swipes do nothing there; its users type.

## States

- **Display mode** shows the full text, "1.234,50 €", or the empty dash.
- **Read-only**: the text can be selected; keys and buttons do not step.
- **Disabled**, **invalid** with its severity, **loading** and the densities: as [TextInput](/docs/forms/text-input#behaviour).

## Messages and localization

From `FormsMessages`: `notANumber`, `numberGrouping`, `numberTooPrecise`, `rangeUnderflow`, `rangeOverflow`, `required`, and `increase` and `decrease` for the stepper buttons. The locale is the prop's, the `Field`'s, the form's or the [`FormsProvider`](/docs/forms/overview)'s; the number logic is forms-core's [Numbers](/docs/forms-core/numbers).
