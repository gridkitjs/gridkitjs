---
title: "Overview"
description: "Framework-free browser behaviours for GridKit renderers: gestures, focus, observers, virtualization, overlays and announcements."
---

@gridkitjs/dom holds every browser behaviour a grid needs that is not drawing: the live region it reports changes through, and more as they move out of the React package. @gridkitjs/core decides what the grid does and runs without a DOM; @gridkitjs/dom does what needs one, with no framework; a renderer such as @gridkitjs/react draws the markup and attaches these behaviours to it.

You only need this package to write a renderer of your own. @gridkitjs/react depends on it already, so installing that is enough to use the grid.

## Install

```ts
npm install @gridkitjs/dom
```

## Live announcer

`createLiveAnnouncer(container?)` adds one visually hidden live region (`role="status"`, `aria-live="polite"`) as the last child of `container` — `document.body` when omitted — and returns `announce(text)` and `destroy()`. The region carries the `gridkit-sr-only` class, which @gridkitjs/theme-tailwind clips to nothing while keeping it in the accessibility tree.

```ts
import { createLiveAnnouncer } from "@gridkitjs/dom";

const announcer = createLiveAnnouncer(gridElement);
announcer.announce("Amount, column 2 of 5");
announcer.announce("Amount, column 2 of 5"); // read out again
announcer.destroy();
```

A live region speaks only when its text changes, so `announce` makes a repeat of the last message a change of its own: the same text twice in a row is read twice.

## Element width

`observeElementWidth(element, onWidth)` reports `element.clientWidth` straight away and again whenever it changes, and returns the function that stops it — the width `resizeMode: "fit"` fills, passed to the controller as `viewportWidth`. The first report is synchronous, so columns laid out before paint never show at the wrong width for a frame.

```ts
import { observeElementWidth } from "@gridkitjs/dom";

const disconnect = observeElementWidth(viewportElement, (width) => {
  controller.setOptions({ ...options, viewportWidth: width });
});
```

## Gestures

A gesture starts from a `PointerPress` — the `pointerdown` that began it, native or a framework's wrapper around one — and only from the main button of the primary pointer: a right-click or a second finger starts nothing, and the starter returns `false`. While it runs, the pointer is captured, so the gesture keeps reporting wherever the pointer goes, and <Kbd>Escape</Kbd> cancels it.

### Column resize

`startColumnResizeGesture(handle, press, session, { onMove, onEnd, onCancel })` drags a column's edge. `session` comes from @gridkitjs/core's `beginColumnResize`, which also turns each pointer position into a clamped width. `onMove(width)` reports every move; `onEnd(width)` reports the release, with `null` when the width ended where it started — a click on the handle is not a resize; `onCancel()` reports <Kbd>Escape</Kbd> or a cancelled pointer.

```ts
import { beginColumnResize } from "@gridkitjs/core";
import { startColumnResizeGesture } from "@gridkitjs/dom";

handle.addEventListener("pointerdown", (event) => {
  const session = beginColumnResize(column, width, event.clientX);
  startColumnResizeGesture(handle, event, session, {
    onMove: (width) => controller.resizeColumn(session.columnId, width, "move"),
    onEnd: (width) => {
      if (width !== null)
        controller.resizeColumn(session.columnId, width, "end");
    },
    onCancel: () =>
      controller.cancelColumnResize(
        session.columnId,
        startSizing,
        session.startWidth,
      ),
  });
});
```

`measureColumnContent(table, columnId)` is the width the widest rendered cell of a column needs to show its content in full — what double-clicking a resize handle sizes it to, through `sizeColumnToContent` — or `null` when the column has no cells.

## Infinite scroll

`attachInfiniteScroll(root, options)` calls `onLoadMore` as a sentinel element — the last row of the body — comes within `rootMargin` of the scrolling `root`, at most once until `isLoadingMore` has gone from `true` back to `false`. It returns `update(options)`, which a renderer calls after every render with the current options and sentinel (the sentinel comes and goes with `hasMore`), and `detach()`.

```ts
import { attachInfiniteScroll } from "@gridkitjs/dom";

const scroll = attachInfiniteScroll(bodyElement, {
  sentinel: lastRow,
  hasMore: true,
  onLoadMore: () => fetchNextPage(),
});

// after each render
scroll.update({ sentinel: lastRow, hasMore, isLoadingMore, onLoadMore });
scroll.detach();
```

When a load finishes but the rows it appended leave the sentinel still in range, the next load starts straight away — nothing would scroll it out and back in to trigger one. With `hasMore` false or no sentinel, nothing is observed.

## Overlay

`attachOverlay(anchor, panel, options)` shows a panel the renderer has already put in the page — a menu, a popover, a filter editor, usually rendered into `document.body` so no scrolling ancestor clips it — beside `anchor`, an element or an `{ x, y }` point, and returns the function that ends it.

```ts
import { attachOverlay } from "@gridkitjs/dom";

const detach = attachOverlay(headerCell, menuElement, {
  placement: "bottom-start",
  gap: 4,
  onDismiss: (reason) => closeMenu(), // removes menuElement, then calls detach()
});
```

| Option          | Type                                                        | Description                                                                                                    |
| --------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `placement`     | `"bottom-start"`, `"top-end"`, `"right-start"` and the rest | Where the panel would rather open. Defaults to `"bottom-start"`.                                               |
| `gap`           | `number`                                                    | Pixels between the anchor and the panel. Defaults to `0`.                                                      |
| `onDismiss`     | `(reason) => void`                                          | Called with `"escape"`, `"outside"`, `"scroll"`, `"resize"` or `"blur"`; the caller closes the panel, or not.  |
| `returnFocusTo` | `HTMLElement \| null`                                       | Where focus goes on detach. Defaults to the element focused when the overlay attached; `null` leaves it alone. |

The panel is positioned `fixed` and opens on the preferred side unless only the opposite side has room for it, lines up with the preferred edge of the anchor unless only the other edge keeps it on screen, and is pushed back inside the viewport if it still overflows. The placement it ends up with is written to `data-gridkit-placement`. Focus moves to the panel's first focusable element, or to the panel itself.

It asks to close on <Kbd>Escape</Kbd>, a pointer down outside it, a scroll anywhere outside it (it is placed in viewport coordinates, so the anchor would move away from it), a window resize, the window losing focus, or focus moving outside it. Nothing on the anchor counts, so a button that toggles the panel closes it with its own click. Detaching returns focus only while focus is still in the panel or nowhere — after a click on another control, focus stays there.

`placeOverlay(anchorRect, panelSize, viewport, { placement, gap })` is the placement on its own: pure arithmetic over boxes, returning `{ top, left, placement }`, for a renderer that positions its own panels.
