---
title: "Toggles"
description: "attachToggle: connects a native checkbox or switch to a forms-core field controller holding a boolean, with a three-state cycle and read-only."
---

`attachToggle(control, controller, options)` connects a native `<input type="checkbox">`, drawn as a checkbox or with `role="switch"`, to a forms-core [field controller](/docs/forms-core/field-state) holding `boolean | null`. Every flip goes through the controller, so it fires the same events as any other field, and the control shows what the controller holds: `checked` for `true`, `indeterminate` for `null`.

<Callout type="note" title="First iteration">
  This API is a first iteration and may change before the first release.
</Callout>

## When to use it

Only to write a forms renderer of your own. [`Checkbox`](/docs/forms/checkbox) and [`Switch`](/docs/forms/switch) attach it for you.

## Example

```ts
import {
  booleanFormatter,
  booleanParser,
  CHECKBOX_WORDS,
  createFieldController,
  defaultFormsMessages,
  type NoDetails,
} from "@gridkitjs/forms-core";
import { attachToggle } from "@gridkitjs/forms-dom";

const control = document.createElement("input");
control.type = "checkbox";
control.setAttribute("aria-label", "Newsletter");
document.body.append(control);

const field = createFieldController<boolean, NoDetails, Event>({
  defaultValue: false,
  defaultParse: booleanParser(CHECKBOX_WORDS),
  defaultFormat: booleanFormatter(CHECKBOX_WORDS),
  messages: defaultFormsMessages,
  // A toggle commits as it flips, so leaving it commits nothing more.
  commitOnLeave: false,
  onCommit: (event) => {
    console.log(
      `${String(event.value)}, by ${event.nativeEvent?.type ?? "code"}`,
    );
  },
});

const toggle = attachToggle(control, field, { threeState: true });

// When the control leaves the page:
toggle.detach();
field.destroy();
```

## Options

| Option       | Type      | Default | Description                                                                                                      |
| ------------ | --------- | ------- | ---------------------------------------------------------------------------------------------------------------- |
| `threeState` | `boolean` | `false` | A flip can set `null`: `false` → `true` → `null` → `false`. Without it, `false` and `null` go to `true`.         |
| `readOnly`   | `boolean` | `false` | Every flip is refused and the control stays focusable. A native checkbox ignores `readonly`, so it is said here. |

## What it does

- The browser's `click`, from a pointer, a label or <Kbd>Space</Kbd>, flips the field to `nextCheckedValue` of its value, through `controller.pick` with `source` and `trigger` `"toggle"`: `onBeforeChange`, `onChange`, `onValidate`, `onBeforeCommit`, `onCommit`.
- `nativeEvent` tells the two apart: a flip by <Kbd>Space</Kbd> carries the Space `keydown`, a press the `click`.
- After every change it writes `checked` and `indeterminate` over whatever the browser did, so a flip `onBeforeChange` prevents leaves the control as it was.
- `focus` and `blur` start and end the edit. Give the controller `commitOnLeave: false`: the flip already committed.
- The field's first error is the control's custom validity, so a plain `<form>` refuses to submit a required box left unchecked.
- A `reset` of the control's form resets the field to its `defaultValue`.

## What it returns

| Member                | Description                                                      |
| --------------------- | ---------------------------------------------------------------- |
| `setOptions(options)` | Replaces the options, from the next event on.                    |
| `detach()`            | Removes every listener and clears the control's custom validity. |
