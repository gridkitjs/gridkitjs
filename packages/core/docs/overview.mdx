@gridkitjs/core is plain TypeScript — so it's testable without a DOM and reusable from other framework adapters. It holds everything the grid decides: column inference, sizing, ordering, selection, sorting, the filtering engine, row grouping, aggregates, pagination, virtualization math, and keyboard navigation. A renderer such as @gridkitjs/react draws the result.

## The view pipeline

[resolveGridView](/docs/core/view) composes the stages into the one view a [renderer](/docs/react#terms) draws: rows are filtered → sorted → grouped → aggregated → paginated, and columns are ordered → hidden → sized. A page holds whole top-level groups, or a set number of data rows under `paginationUnit: "row"`, and aggregates are computed before pagination, so a subtotal never depends on which page is showing. createGridViewResolver is its memoised form, which recomputes only the stages a change touches.

## Grid options

`GridOptions<Row>` is every setting of a grid that names no renderer's types: `dataSource` and `getRowId`, what the user may do (`sortableColumns`, `selectable`, `paginated`…), the state it starts in (`defaultColumnSort`, `defaultPagination`…), the callbacks that report changes (`onColumnSortChange`…), the row hooks (`onRowClick`, `onRowDoubleClick`, and `getRowProps` for a row's class and `data-*` attributes), `locale`, `messages`, `contextMenu` and `onContextMenuOpenChange` (see [context menus](/docs/core/commands#context-menus)), `commands` and `onCommand` (see [app commands](/docs/core/commands#on-a-grid)), and `toolbar` (see [toolbar](/docs/core/toolbar#the-option)). A renderer's own props are these plus what only it can express — @gridkitjs/react's `DataGridProps` adds `columns`, the pager and infinite-scroll templates, `renderToolbarItem`, the selection callbacks and `ref` — so a setting means the same thing, under the same name, in every renderer.

### Messages

`GridMessages` is every string a grid shows or announces of its own — the pager, the group-by bar, the loading row, boolean and blank values, the built-in commands' labels, the menus' names, the toolbar's name, search box and "More" button, the column chooser's name, search box and "Show all", and the live-region announcements. `defaultMessages` holds the English a grid speaks unless told otherwise, its counts grouped in the runtime's locale; `createDefaultMessages(locale)` is the same English counting in `locale`'s digits — "1,204 of 10,000 rows" under `"en"`, "1.204 of 10.000 rows" under `"de-DE"`. `resolveMessages(messages, locale)` lays a partial `messages` option over the defaults for `locale`, returning the defaults themselves — the same object for the same locale — when given none. A message naming something is a function — `pageStatus: (page, pageCount) => string` — so a translation puts the name where its grammar wants it. See [localization](/docs/react/localization) for every key.

## The controller

[createGridController](/docs/core/controller) holds a grid's state, derives its view and carries every action a user can take, with each slice of state controlled or uncontrolled on its own. A renderer creates one per grid, feeds it its options and draws the view, so the renderer decides nothing the user can see.

## Commands and menus

A [command](/docs/core/commands) is the one implementation behind a menu item, a toolbar button and the API — "Sort ascending", "Hide column", "Clear filters". It decides whether it shows and whether it can run from a snapshot of the grid, and acts through the controller's actions. `builtInCommands` is the grid's own set; `resolveCommands` lays an app's commands over it, replacing a built-in by id. A menu is a list of command ids, separators, inline items and submenus, which `resolveMenu` turns into what a renderer draws.

## Filters and filter editors

A filter is plain data — operator entries such as `{ kind: "operator", columnId: "amount", operator: "between", value: [10, 100] }` save and restore with the rest of the state. The [filter-editor model](/docs/core/filtering) is what a column's filter UI is drawn over: the shape of the column's filter, its values with counts cascaded over the other filters, and a draft reducer for a checklist or condition editor.

## Entry points

The package has two entry points, and each name is exported from one of them:

- `@gridkitjs/core` is for apps: the grid's data, options and state, the controller, commands, menu and toolbar options, the view pipeline's functions, messages, formatting and export. An app using a ready-made renderer such as @gridkitjs/react imports from here, if it imports from core at all.
- `@gridkitjs/core/renderer` is for someone writing a renderer: how its menus, toolbar, header and filter editor are driven, where focus and drops land, the column resize session, the pager's window and the virtualizer's range. It may change in a minor release; see [stability](/docs/react/stability).

```ts
import { createGridController, paginateRows } from "@gridkitjs/core";
import { paginationWindow } from "@gridkitjs/core/renderer";
```

Each page that lists renderer building blocks says which ones come from `@gridkitjs/core/renderer`.

See [column definitions](/docs/core/column-definitions) for column inference, [resizing](/docs/core/resizing) and [ordering](/docs/core/ordering) for the logic underneath resizableColumns and reorderableColumns, or [selection](/docs/core/selection) for the primitives underneath selectable.
