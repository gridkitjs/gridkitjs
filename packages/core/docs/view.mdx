title: "The view pipeline"
description: "resolveGridView: rows, columns, state and options in; everything the grid shows out."
---

`resolveGridView` is the one function that answers "what is the user looking at". It takes the rows, the column definitions, the grid's state and its options, and runs every stage DataGrid renders from: rows are filtered → sorted → grouped → aggregated → paginated, and columns are ordered → hidden → sized. Call it from a custom adapter, an export or a toolbar instead of composing the stages yourself, so nothing can disagree with what the grid shows.

```ts
import { resolveGridView } from "@gridkitjs/core";

const view = resolveGridView({
  rows,
  getRowId: (row) => String(row.Id),
  columns,
  state: {
    columnSort: [{ columnId: "Amount", direction: "desc" }],
    groupBy: [{ columnId: "Region" }],
  },
  options: { paginated: true, aggregates: [{ columnId: "Amount", fn: "sum" }] },
});

view.pageRows; // the current page: group headers and data rows, in render order
view.grandTotal.get("Amount"); // the sum over every filtered row, on every page
```

## Functions

| Function                                        | Type                                 | Description                                                                                                                                                                  |
| ----------------------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `resolveGridView(input)`                        | `GridView<Row, Node>`                | Derives the whole view in one call, with no memory of earlier calls.                                                                                                         |
| `createGridViewResolver()`                      | `(input: GridViewInput) => GridView` | A memoised `resolveGridView`. Each stage keeps its last inputs and returns its last output when none changed, so a call recomputes only what a change touches.               |
| `resolveShownRows(rows, filter, sort, columns)` | `readonly ResolvedRow<Row>[]`        | The data stages before grouping on their own: `rows` filtered with `filterRows`, then sorted with `sortRows`. Filtering first only saves work; the order comes out the same. |

## `GridView`

| Field             | Type                             | Description                                                                                                                         |
| ----------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `dataColumns`     | `readonly DataColumn<Row>[]`     | Every column, hidden ones included, ordered, as `{ id, column }` — no width. What filtering, sorting, grouping and aggregates read. |
| `columns`         | `readonly ResolvedColumn<Row>[]` | The columns as rendered: visible, ordered and sized.                                                                                |
| `rows`            | `readonly ResolvedRow<Row>[]`    | The rows, filtered then sorted.                                                                                                     |
| `displayRows`     | `readonly DisplayRow<Row>[]`     | `rows` grouped, each group header carrying its aggregates — every page.                                                             |
| `pageRows`        | `readonly DisplayRow<Row>[]`     | The current page of `displayRows`. All of it when not paginated. What a page holds follows `paginationUnit`.                        |
| `displayDataRows` | `readonly ResolvedRow<Row>[]`    | `pageRows` without group headers or summary rows — the data rows on screen, in display order.                                       |
| `pageCount`       | `number`                         | `1` when not paginated.                                                                                                             |
| `pageIndex`       | `number`                         | The page shown, clamped into range. `0` when not paginated.                                                                         |
| `grandTotal`      | `AggregateResults`               | Every aggregate over all of `rows`, ignoring grouping and pagination.                                                               |

## Input

`state` holds any of the slices of a `GridViewState<Row>`: `columnSizing`, `columnOrder`, `columnVisibility`, `columnSort`, `filter`, `groupBy`, `groupExpansion` and `pagination`, each the same type as the matching `default*` prop on DataGrid. They are every slice of `GridState` but the three selections, which change what is highlighted and never what is shown, so a whole `GridState` serves too. A slice left out, or `undefined`, reads as the grid's starting default:

| Field              | Default                               |
| ------------------ | ------------------------------------- |
| `columnSizing`     | `{}`: each column at its own width    |
| `columnOrder`      | `[]`: the order of `columns`          |
| `columnVisibility` | `{}`: hidden only where `hidden` says |
| `columnSort`       | `[]`                                  |
| `filter`           | `[]`                                  |
| `groupBy`          | `[]`                                  |
| `groupExpansion`   | `{ mode: "allExpanded", except: [] }` |
| `pagination`       | `{ pageIndex: 0, pageSize: 25 }`      |

`options` is a `GridViewOptions<Row>`; every field is optional and defaults the way DataGrid's prop of the same name does:

| Option                                                              | Default    | Description                                                                                                                                               |
| ------------------------------------------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `paginated`                                                         | `false`    | Whether `pageRows` is one page rather than every row.                                                                                                     |
| `paginationUnit`                                                    | `"group"`  | What a page's `pageSize` counts once grouped: top-level groups, or `"row"` for data rows. See [what a page counts](/docs/core/paging#what-a-page-counts). |
| `aggregates`                                                        | `[]`       | The aggregates to compute, per group and in `grandTotal`.                                                                                                 |
| `groupAggregateDisplay`                                             | `"inline"` | `"row"` adds a summary row after each group.                                                                                                              |
| `columnSizeDefaults`                                                | —          | Width and bounds for a column that sets none.                                                                                                             |
| `resizableColumns`, `reorderableColumns`, `groupByDraggableColumns` | `false`    | Grid-level defaults a column's own setting overrides.                                                                                                     |
| `resizeMode`                                                        | `"fit"`    | `"fit"` stretches or squeezes columns to fill `viewportWidth`; `"fixed"` keeps their widths.                                                              |
| `viewportWidth`                                                     | `null`     | The width to fit. Leave it out where there is no viewport, such as an export.                                                                             |

A column hidden by its definition's `hidden` or by `columnVisibility` leaves `columns` but stays in `dataColumns`, so a sort, filter or grouping on it still applies, and it keeps its slot in the column order for when it is shown again. `isColumnVisible(column, visibility)` answers for one column, `applyColumnVisibility(dataColumns, visibility)` drops the hidden ones, and `setColumnVisibility(dataColumns, visibility, columnIds, visible)` returns the next state, or the same one when nothing changes.

`columns` is used as given: inferring columns from the rows when a grid is given none is the [controller](/docs/core/controller)'s job, done before it resolves the view.

## Memoisation

Hold one `createGridViewResolver()` per grid and call it with the current input whenever the view is needed. Stages compare their inputs by identity, so pass state slices as the same objects until they change. A slice left out reads as the same default object on every call. The data stages read `dataColumns`, which carry no width, so a resize or a viewport change re-sizes `columns` and leaves `rows`, `displayRows`, `pageRows`, `displayDataRows` and `grandTotal` exactly as they were — the same references. The returned view object itself is reused when nothing in it changed.

```ts
const resolve = createGridViewResolver<Row>();

const before = resolve(input);
const after = resolve({
  ...input,
  state: { ...input.state, columnSizing: { Amount: 180 } },
});

after.rows === before.rows; // true — filtering and sorting did not run again
after.columns === before.columns; // false — the widths changed
```
