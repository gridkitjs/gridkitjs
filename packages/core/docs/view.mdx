title: "The view pipeline"
description: "resolveGridView: rows, columns, state and options in; everything the grid shows out."
---

`resolveGridView` is the one function that answers "what is the user looking at". It takes the rows, the column definitions, the grid's state and its options, and runs every stage DataGrid renders from: rows are filtered → sorted → grouped → aggregated → paginated, and columns are ordered → hidden → pinned → sized. Call it from a custom adapter, an export or a toolbar instead of composing the stages yourself, so nothing can disagree with what the grid shows.

```ts
import { resolveGridView } from "@gridkitjs/core";

const view = resolveGridView({
  rows,
  getRowId: (row) => String(row.Id),
  columns,
  state: {
    columnSort: [{ columnId: "Amount", direction: "desc" }],
    groupBy: [{ columnId: "Region" }],
  },
  options: { paginated: true, aggregates: [{ columnId: "Amount", fn: "sum" }] },
});

view.pageRows; // the current page: group headers and data rows, in render order
view.grandTotal.get("Amount"); // the sum over every filtered row, on every page
```

## Functions

| Function                                        | Type                                 | Description                                                                                                                                                                  |
| ----------------------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `resolveGridView(input)`                        | `GridView<Row, Node>`                | Derives the whole view in one call, with no memory of earlier calls.                                                                                                         |
| `createGridViewResolver()`                      | `(input: GridViewInput) => GridView` | A memoised `resolveGridView`. Each stage keeps its last inputs and returns its last output when none changed, so a call recomputes only what a change touches.               |
| `resolveShownRows(rows, filter, sort, columns)` | `readonly ResolvedRow<Row>[]`        | The data stages before grouping on their own: `rows` filtered with `filterRows`, then sorted with `sortRows`. Filtering first only saves work; the order comes out the same. |

## `GridView`

| Field             | Type                             | Description                                                                                                                                |
| ----------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `dataColumns`     | `readonly DataColumn<Row>[]`     | Every column, hidden ones included, ordered, as `{ id, column }` — no width. What filtering, sorting, grouping and aggregates read.        |
| `columns`         | `readonly ResolvedColumn<Row>[]` | The columns as rendered: visible, ordered and sized, with the columns pinned to the start first and those pinned to the end last.          |
| `rows`            | `readonly ResolvedRow<Row>[]`    | The rows, filtered then sorted. Under `dataMode: "server"`, as given.                                                                      |
| `displayRows`     | `readonly DisplayRow<Row>[]`     | `rows` grouped, each group header carrying its aggregates: every page, or under `dataMode: "server"` the one page given.                   |
| `pageRows`        | `readonly DisplayRow<Row>[]`     | The current page of `displayRows`. All of it when not paginated or under `dataMode: "server"`. What a page holds follows `paginationUnit`. |
| `displayDataRows` | `readonly ResolvedRow<Row>[]`    | `pageRows` without group headers or summary rows — the data rows on screen, in display order.                                              |
| `pageCount`       | `number`                         | `1` when not paginated. Counted from `rowCount` under `dataMode: "server"`.                                                                |
| `pageIndex`       | `number`                         | The page shown, clamped into range. `0` when not paginated.                                                                                |
| `rowCount`        | `number`                         | How many rows the grid has across every page, as `aria-rowcount` counts them: see [row count](#row-count).                                 |
| `grandTotal`      | `AggregateResults`               | Every aggregate over all of `rows`, ignoring grouping and pagination.                                                                      |

## Input

`state` holds any of the slices of a `GridViewState<Row>`: `columnSizing`, `columnOrder`, `columnVisibility`, `columnPinning`, `columnSort`, `filter`, `groupBy`, `groupExpansion` and `pagination`, each the same type as the matching `default*` prop on DataGrid. They are every slice of `GridState` but the three selections, which change what is highlighted and never what is shown, so a whole `GridState` serves too. A slice left out, or `undefined`, reads as the grid's starting default:

| Field              | Default                               |
| ------------------ | ------------------------------------- |
| `columnSizing`     | `{}`: each column at its own width    |
| `columnOrder`      | `[]`: the order of `columns`          |
| `columnVisibility` | `{}`: hidden only where `hidden` says |
| `columnPinning`    | `{}`: pinned only where `pinned` says |
| `columnSort`       | `[]`                                  |
| `filter`           | `[]`                                  |
| `groupBy`          | `[]`                                  |
| `groupExpansion`   | `{ mode: "allExpanded", except: [] }` |
| `pagination`       | `{ pageIndex: 0, pageSize: 25 }`      |

`options` is a `GridViewOptions<Row>`; every field is optional and defaults the way DataGrid's prop of the same name does:

| Option                                                              | Default    | Description                                                                                                                                                                                   |
| ------------------------------------------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dataMode`                                                          | `"client"` | `"server"` when the app's server sorts, filters and pages the rows. See [server data mode](#server-data-mode).                                                                                |
| `rowCount`                                                          | —          | Under `dataMode: "server"`, how many rows the server has for the current filter. The rows given when left out.                                                                                |
| `paginated`                                                         | `false`    | Whether `pageRows` is one page rather than every row.                                                                                                                                         |
| `paginationUnit`                                                    | `"group"`  | What a page's `pageSize` counts once grouped: top-level groups, or `"row"` for data rows. See [what a page counts](/docs/core/paging#what-a-page-counts). Ignored under `dataMode: "server"`. |
| `aggregates`                                                        | `[]`       | The aggregates to compute, per group and in `grandTotal`.                                                                                                                                     |
| `groupAggregateDisplay`                                             | `"inline"` | `"row"` adds a summary row after each group.                                                                                                                                                  |
| `columnSizeDefaults`                                                | —          | Width and bounds for a column that sets none.                                                                                                                                                 |
| `resizableColumns`, `reorderableColumns`, `groupByDraggableColumns` | `false`    | Grid-level defaults a column's own setting overrides.                                                                                                                                         |
| `resizeMode`                                                        | `"fit"`    | `"fit"` stretches or squeezes columns to fill `viewportWidth`; `"fixed"` keeps their widths.                                                                                                  |
| `viewportWidth`                                                     | `null`     | The width to fit. Leave it out where there is no viewport, such as an export.                                                                                                                 |

A column hidden by its definition's `hidden` or by `columnVisibility` leaves `columns` but stays in `dataColumns`, so a sort, filter or grouping on it still applies, and it keeps its slot in the column order for when it is shown again. `isColumnVisible(column, visibility)` answers for one column, `applyColumnVisibility(dataColumns, visibility)` drops the hidden ones, and `setColumnVisibility(dataColumns, visibility, columnIds, visible)` returns the next state, or the same one when nothing changes.

`columns` is used as given: inferring columns from the rows when a grid is given none is the [controller](/docs/core/controller)'s job, done before it resolves the view.

## Server data mode

`dataMode`, a `DataMode`, says who sorts, filters and pages the rows. Under `"client"`, the default, the pipeline does, over every row it is given. Under `"server"` the app's server already has, and `rows` is the result as it came back:

- The rows are neither filtered nor sorted: they show in the order given. `columnSort` and `filter` still describe what the user asked for, so the app sends them with its next request.
- With `paginated` on, `rows` is the page `pagination.pageIndex` names. Every row given is shown, `pageCount` is `countPages(rowCount, pageSize)`, and `pageIndex` is clamped into it. Without `rowCount`, pages are counted from the rows given.
- Each row on the page has its `datasetIndex` offset by `pageIndex * pageSize`, so it is still the row's place in the whole result; `rowIndex` numbers the rows on the page.
- Row grouping groups the rows given, and group headers add nothing to the page count. `paginationUnit` is ignored. Aggregates and `grandTotal` cover the rows given.
- With `paginated` off, as for infinite scroll, the rows given are one page numbered from `0`.

```ts
import { resolveGridView } from "@gridkitjs/core";

// The server's answer for page 4 at 25 a page: 25 of its 230 rows.
const view = resolveGridView({
  rows: response.rows,
  columns,
  state: { pagination: { pageIndex: 3, pageSize: 25 } },
  options: { dataMode: "server", paginated: true, rowCount: response.total },
});

view.pageCount; // 10
view.pageRows[0]?.datasetIndex; // 75
```

## Row count

`rowCount` on the view is the number of rows a renderer puts in `aria-rowcount` and announces, besides its header and footer rows. Under `"client"` it is every entry of `displayRows` across every page: data rows, group headers and summary rows, without the rows a collapsed group hides. Under `"server"` it is the `rowCount` option, or the rows given without one, plus the group headers and summary rows among the rows given, less the rows a collapsed group hides there. Group headers on other pages are never seen, so a grouped server grid counts only this page's.

## Pinned columns

A column is pinned to the grid's inline start or end edge by its definition's `pinned`, or by `columnPinning`, a `ColumnPinningState`: column id to `"start"`, `"end"` or `"none"` (a `ColumnPin`), holding only the columns that were changed, so `"none"` unpins a column its definition pins. `columns` lists the columns pinned to the start first and those pinned to the end last, each group in column order. `dataColumns` and `columnOrder` keep column order, so a column unpinned goes back to its place.

Each `ResolvedColumn` in `columns` says where it sits, so a renderer draws pinned columns from the view alone:

| Field       | Type                         | Description                                                                                                                              |
| ----------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `pinned`    | `"start" \| "end" \| "none"` | The edge the column is pinned to, after the state.                                                                                       |
| `pinOffset` | `number`                     | How far, in px, it sits from its edge: the summed widths of the columns pinned to the same edge between it and that edge. `0` otherwise. |
| `pinEdge`   | `boolean`                    | Whether it is the last column pinned to the start or the first pinned to the end — the one beside the scrolling columns.                 |

Offsets are worked out after sizing, so under `"fit"` they follow the fitted widths, and a hidden pinned column adds nothing to any of them. `resolveColumnPin(column, pinning)` answers for one column, `applyColumnPinning(dataColumns, pinning)` puts a column list in pinned order, and `setColumnPin(dataColumns, pinning, columnId, pin)` returns the next state, or the same one when nothing changes. `pinnedWidths(columns)`, from `@gridkitjs/core/renderer`, returns `{ start, end }`: the width the columns pinned to each edge cover, which a renderer keeps scrolled content clear of.

## Memoisation

Hold one `createGridViewResolver()` per grid and call it with the current input whenever the view is needed. Stages compare their inputs by identity, so pass state slices as the same objects until they change. A slice left out reads as the same default object on every call. The data stages read `dataColumns`, which carry no width, so a resize, a viewport change, or a column hidden or pinned re-sizes `columns` and leaves `rows`, `displayRows`, `pageRows`, `displayDataRows` and `grandTotal` exactly as they were — the same references. The returned view object itself is reused when nothing in it changed.

```ts
const resolve = createGridViewResolver<Row>();

const before = resolve(input);
const after = resolve({
  ...input,
  state: { ...input.state, columnSizing: { Amount: 180 } },
});

after.rows === before.rows; // true — filtering and sorting did not run again
after.columns === before.columns; // false — the widths changed
```
