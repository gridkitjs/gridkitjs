---
title: "Pagination"
description: "The pagination logic underneath paginated and the numbered pager."
---

`paginateRows` slices the grid's rows into pages, and `paginationWindow` works out which page numbers a numbered pager shows. The [view pipeline](/docs/core/view) pages for you under `paginated`; reach for these directly in a custom adapter or a pager of your own. `paginateRows` comes from `@gridkitjs/core`, and `paginationWindow`, which serves a pager's drawing, from `@gridkitjs/core/renderer`.

A `PaginationState` is `{ pageIndex, pageSize }`, with `pageIndex` 0-based.

## Functions

| Function                                             | Type                               | Description                                                                                                                                                                                                                    |
| ---------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `paginateRows(rows, pagination, options?)`           | `PaginatedRows<Row>`               | The page `pagination` names, from rows already filtered, sorted, grouped and aggregated. A `pageIndex` out of range is clamped, and a `pageSize` below `1` is taken as `1`. `options` is `{ unit? }`, see below.               |
| `paginationWindow(currentPage, pageCount, options?)` | `readonly PaginationWindowEntry[]` | The 1-based page numbers a numbered pager shows for `currentPage` of `pageCount`, always the same number of entries once there are more pages than fit. `options` is `{ boundaryCount?, siblingCount? }`, both `1` by default. |

A page counts **units**: a top-level group with everything under it by default, or a data row, as [what a page counts](#what-a-page-counts) sets out.

`PaginatedRows<Row>` is what `paginateRows` returns:

| Field       | Type                         | Description                                                                                                                          |
| ----------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `rows`      | `readonly DisplayRow<Row>[]` | The page's rows, with `rowIndex` renumbered from `0` at the top of the page. `datasetIndex` keeps each row's place in the whole set. |
| `pageCount` | `number`                     | How many pages the rows make at this size — `0` for no rows.                                                                         |
| `pageIndex` | `number`                     | The page returned: `pagination.pageIndex`, clamped. Read this back rather than trusting the one passed in.                           |

```ts
import { paginateRows } from "@gridkitjs/core";
import { paginationWindow } from "@gridkitjs/core/renderer";

const page = paginateRows(displayRows, { pageIndex: 6, pageSize: 25 });
page.pageIndex; // 6, or the last page if there are fewer than 7

paginationWindow(page.pageIndex + 1, page.pageCount);
// [1, "ellipsis", 6, 7, 8, "ellipsis", 20] for page 7 of 20
```

`paginationWindow` always keeps the first and last `boundaryCount` pages and a run of `2 * siblingCount + 1` pages around the current one, slid inwards near either end rather than cut short. Between each boundary and that run sits one slot: the page it skips when it skips only one, an `"ellipsis"` otherwise.

So the window has a constant length. Once `pageCount` is more than `2 * boundaryCount + 2 * siblingCount + 3` (7 with the defaults), every page's window has exactly that many entries, and a pager that gives each entry the same width keeps its next and last buttons in place as the user pages through. Up to that many pages, every page shows.

```ts
paginationWindow(1, 20); // [1, 2, 3, 4, 5, "ellipsis", 20]
paginationWindow(10, 20); // [1, "ellipsis", 9, 10, 11, "ellipsis", 20]
paginationWindow(20, 20); // [1, "ellipsis", 16, 17, 18, 19, 20]
```

## What a page counts

`pageSize` counts **units**, and `options.unit`, a `PaginationUnit`, says what a unit is once the rows are grouped. An ungrouped grid pages by data rows under either.

| Unit                | A unit is                                       | A page of 25 holds                                                                      |
| ------------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------- |
| `"group"` (default) | A top-level group with everything under it.     | 25 top-level groups, however many rows they have. A group never splits across pages.    |
| `"row"`             | A data row, or the header of a collapsed group. | 25 data rows and collapsed groups, plus the headers and summary rows that go with them. |

Under `"group"`, a group's summary row stays with its group. Under `"row"`, a page that continues a group starts with that group's header again, and every enclosing group's header above it, so the rows on it are never shown without their group. A repeated header is the same row as on the page before: the same `groupId`, `datasetIndex` and aggregates, so expanding or collapsing it acts on the one group. Expanded headers and summary rows take no place of their own: a header goes with its group's first row, and a summary row with its group's last, on whichever page that is. A collapsed group takes one place, so it is never left off every page.

```ts
import { paginateRows } from "@gridkitjs/core";

// 100,000 rows in 4 groups: a page holds 25 data rows and their groups' headers.
const page = paginateRows(
  displayRows,
  { pageIndex: 0, pageSize: 25 },
  { unit: "row" },
);
```

The view pipeline and the controller take the unit from the `paginationUnit` option, so the page shown, the page count and a clamped `pageIndex` always agree.
