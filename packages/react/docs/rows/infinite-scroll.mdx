---
title: "Infinite scroll"
description: "Loading more rows as the user scrolls near the bottom, instead of pagination."
---

`infiniteScroll` loads more rows as the user scrolls near the bottom of the grid's body, in place of `paginated`'s page-by-page navigation. It takes a config object: `hasMore` and `onLoadMore` are required, everything else tunes presentation.

```tsx
<DataGrid
  columns={columns}
  dataSource={rows}
  height={400}
  infiniteScroll={{
    hasMore,
    isLoadingMore,
    onLoadMore: () => {
      // fetch the next page and append it to `rows`
    },
  }}
/>
```

- `hasMore` — whether a further `onLoadMore` could still return more rows. `false` removes the loading [sentinel row](/docs/react#terms) entirely, so no further scrolling can trigger a load.
- `onLoadMore` — called at most once per genuine threshold-crossing: when the sentinel comes within `rootMargin` of the body's visible area. Not again until the load finishes (`isLoadingMore` back to `false`), `hasMore` changes, or the sentinel leaves `rootMargin` and comes back.
- `isLoadingMore` — whether a load triggered by `onLoadMore` is still in flight. Suppresses further calls to it until this goes back to `false`.

`paginated` and `infiniteScroll` are two different answers to the same question: how the grid moves through more rows than fit on screen. They do not compose. Setting both logs a dev-time `console.error` and only `paginated` takes effect.

</Callout>

The message reads:

```tsx
// console.error: DataGrid: `paginated` and `infiniteScroll` are
// mutually exclusive — only `paginated` takes effect while both are set.
<DataGrid paginated infiniteScroll={{ hasMore, onLoadMore }} />
```

## `rootMargin` fires the load early

The grid watches its last row against its own scrollable body, not the page, so loading works even when the grid sits in a page that does not scroll. `rootMargin` (default `"200px"`) widens that area, so `onLoadMore` fires while the last row is still `rootMargin` away from view rather than only once the user reaches the bottom:

```tsx
<DataGrid
  columns={columns}
  dataSource={rows}
  height={400}
  infiniteScroll={{ hasMore, onLoadMore, rootMargin: "400px" }}
/>
```

## The loading row

While `isLoadingMore` is `true`, a "Loading more…" row (`messages.loadingMore`) renders above the sentinel. `loadingTemplate` replaces it, as `pager.template` does for the pager:

```tsx
<DataGrid
  columns={columns}
  dataSource={rows}
  height={400}
  infiniteScroll={{
    hasMore,
    isLoadingMore,
    onLoadMore,
    loadingTemplate: () => <Spinner />,
  }}
/>
```

Both the loading row and the sentinel are presentational: neither counts toward `aria-rowcount`, and neither is a stop keyboard navigation's arrow keys can land on .

## Appends only

Unlike `paginated`, which returns to the first page when a filter, sort or group-by change shrinks the result, `infiniteScroll` never resets: it only appends what `onLoadMore` provides. If `dataSource` changes for another reason, the grid checks the new rows on the next render and loads again if the last row is still in range.

## A load that fails

The grid has no retry or backoff. A load that fails and sets `isLoadingMore` back to `false` while the last row is still in range is asked for again at once. To stop that, set `hasMore` to `false` until the user asks again, or keep `isLoadingMore` `true` while the failure is shown. [Server-side data](/docs/react/server-side-data#loading-more-as-the-user-scrolls) does the first.

## Pair with `virtualized`

`infiniteScroll` and [`virtualized`](/docs/react/row-virtualization) are independent — they work with or without each other. But a grid that mounts every row it has loaded keeps growing its DOM, which is the problem virtualization solves. For a dataset that grows without bound, pair the two (a recommendation, not a requirement):

```tsx
<DataGrid
  columns={columns}
  dataSource={rows}
  height={400}
  virtualized
  infiniteScroll={{ hasMore, isLoadingMore, onLoadMore }}
/>
```

## Props

`infiniteScroll` takes an `InfiniteScrollConfig`:

| Prop              | Type              | Default   | Description                                                         |
| ----------------- | ----------------- | --------- | ------------------------------------------------------------------- |
| `hasMore`         | `boolean`         | —         | Whether a further `onLoadMore` could still return more rows.        |
| `onLoadMore`      | `() => void`      | —         | Called at most once per threshold-crossing.                         |
| `isLoadingMore`   | `boolean`         | `false`   | Suppresses `onLoadMore` until this goes back to `false`.            |
| `rootMargin`      | `string`          | `"200px"` | `IntersectionObserver` `rootMargin` — how early `onLoadMore` fires. |
| `loadingTemplate` | `() => ReactNode` | —         | Replaces the built-in "Loading more…" row.                          |
