`headerTemplate` and `cellTemplate` draw a header or a cell with any React node, so markup and conditional styling are plain component code. Start from `defineColumnsFromRows` for the columns you don't need to customize, then declare the ones you do.

## When you need a template

A column without a template already shows its value as text — formatted through `Intl` (dates, numbers, currencies, percentages) once it has a `format` or the grid a `locale` — and a header without one shows the column's `header` text. So reach for `format` or `valueFormatter` when only the text should change, and `header` when the header is just a name; see [formatting values](/docs/react/column-definition#formatting-values).

A template is for markup: a link or a button in a cell, a badge, a style that depends on the row, an icon in a header. A `cellTemplate` receives the raw `value`, not the formatted text. A `headerTemplate` can sit beside a `header`: the template is what the header shows, and `header` is what screen-reader announcements call the column, since markup need not be text.

## The `cellTemplate` context

`cellTemplate` receives a single `CellTemplateContext<Row>` argument rather than positional arguments, so a later addition to it is not a breaking change to every template already written.

| Field          | Type      | Description                                                                                                                                               |
| -------------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `value`        | `unknown` | This cell's value, read off the column's `field` path. Untyped since a dotted path's type can't be recovered here — a template narrows it.                |
| `row`          | `Row`     | The whole row, for a template that needs a sibling field.                                                                                                 |
| `rowIndex`     | `number`  | Position among the rows as rendered — filtered, sorted, and paginated once `paginated` is on. Not the raw `dataSource` index.                             |
| `datasetIndex` | `number`  | This row's absolute position in the whole filtered/sorted/grouped dataset, unaffected by which page is showing. See [pagination](/docs/react/pagination). |
| `rowId`        | `string`  | This row's id, as `getRowId` (or the position fallback) resolved it.                                                                                      |
| `selected`     | `boolean` | Whether this row is selected, so a template can style itself to match.                                                                                    |

## Styling a template

A class in a template is your own code, so it reaches the page the way any class in your app does. Tailwind utilities work as long as your app's Tailwind build scans the file the template is in. Tailwind v4 scans your project's source files automatically; a template in a file it skips, such as one in `node_modules` or a gitignored folder, needs an `@source` line for that path. The theme itself ships no utilities for your templates.

The theme does register its palette as colours, so `text-accent`, `text-fg-muted`, `bg-selected` and the rest follow the grid's light and dark mode with no colours of your own:

```tsx title="App.tsx"
import { DataGrid, type ColumnDefinition } from "@gridkitjs/react";

interface Deployment {
  id: number;
  service: string;
  status: "healthy" | "degraded";
  cost: number;
}

const deployments: Deployment[] = [
  { id: 1, service: "checkout-api", status: "healthy", cost: 1240.5 },
  { id: 2, service: "billing-worker", status: "degraded", cost: 860.2 },
  { id: 3, service: "search-index", status: "healthy", cost: 92.75 },
];

const currency = new Intl.NumberFormat("en-US", {
  style: "currency",
  currency: "USD",
});

const columns: readonly ColumnDefinition<Deployment>[] = [
  { field: "service", header: "Service" },
  {
    field: "status",
    header: "Status",
    cellTemplate: ({ row }) => (
      <span
        className={
          row.status === "healthy"
            ? "text-fg-muted"
            : "font-semibold text-accent"
        }
      >
        {row.status}
      </span>
    ),
  },
  {
    field: "cost",
    header: "Cost",
    type: "currency",
    cellTemplate: ({ row }) => currency.format(row.cost),
  },
];

export default function App() {
  return (
    <DataGrid
      columns={columns}
      dataSource={deployments}
      getRowId={(row) => String(row.id)}
      label="Deployments"
    />
  );
}
```

Without Tailwind, give the element a class of your own and style it in your stylesheet, reading the theme's tokens such as `var(--gridkit-accent)`. For a class on every cell of a column, rather than on markup inside it, use the column's `cellClassName` or `headerClassName`; see [column definition](/docs/react/column-definition).
