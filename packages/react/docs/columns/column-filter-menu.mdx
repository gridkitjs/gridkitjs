---
title: "Column filter menu"
description: "A filter popup per column, opened from its header — its sort entries, its editor, and Clear filter, Cancel and OK — turned on with filterableColumns."
---

A column with a filter menu opens a small dialog below its header for filtering that column: the column's sort entries at the top, an editor for its filter, and buttons to clear the filter, cancel or apply. It edits the grid's one [filter](/docs/react/column-filtering), so the menu, the toolbar's search box, `setFilter` and a controlled `filter` always agree.

## Turning it on

```tsx
<DataGrid
  columns={[
    { field: "Id", filterable: false },
    { field: "Customer" },
    { field: "Amount", type: "number" },
  ]}
  dataSource={orders}
  sortableColumns
  filterableColumns
  contextMenu
/>
```

`filterableColumns` gives every column a filter menu unless the column's own `filterable` says otherwise; it is off by default, like `sortableColumns`. The filter applies either way: a column without a menu is still filtered by `defaultFilter`, `setFilter` or a search.

| Prop                | Type      | Default | Description                                                        |
| ------------------- | --------- | ------- | ------------------------------------------------------------------ |
| `filterableColumns` | `boolean` | `false` | Whether columns get a filter menu, unless a column says otherwise. |
| `column.filterable` | `boolean` |         | Per-column override of `filterableColumns`.                        |

## Opening it

- **The header's filter button.** A filterable header shows a funnel at its end, beside the sort toggle — faint until the header is hovered or focused, and marked while the column is filtered. Pressing it opens the menu, and pressing it again closes it.
- **The keyboard.** <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd>+<Kbd>ArrowDown</Kbd> on a focused header opens it. The header's `aria-keyshortcuts` lists the key, as it does its others.
- **A header's context menu.** With [`contextMenu`](/docs/react/context-menu) on, a filterable header's menu lists "Filter…" after its sort entries, then "Clear filter", which clears the column's filter without opening anything — disabled while the column is not filtered.
- **The ref.** `openFilterMenu(columnId)` opens it, and returns whether it did: not for a column with no filter menu, nor a hidden one, which has no header to open below. `closeFilterMenu()` closes it, leaving the column chooser alone. `runCommand("filter.open", { area: "header", columnId })` opens it too, reporting to `onCommand` as the API's.

It opens below the header and gives focus back to it when it closes. Only one panel is open at a time: opening a filter menu replaces the column chooser, or another column's filter menu.

```tsx
const gridRef = useRef<DataGridApi<Order>>(null);

<DataGrid
  ref={gridRef}
  columns={columns}
  dataSource={orders}
  filterableColumns
/>;

<button onClick={() => gridRef.current?.openFilterMenu("Customer")}>
  Filter customers
</button>;
```

## The filtered state

While a column with a filter menu is filtered — by the menu, `setFilter`, a controlled `filter` or anything else naming the column — its header's filter button stays shown, in accent, and the header carries `aria-description="Filtered"`, so a screen reader says so as it reads the header. A search across every column marks none, and a column without a filter menu shows no filtered state, however it is filtered.

## What it shows

- **The column's sort entries** — "Sort ascending", "Sort descending" and "Clear sort", the header menu's own — while the column [sorts](/docs/react/column-sorting). Choosing one sorts the column and closes the menu; "Sort ascending" or "Sort descending" is pressed while the column sorts that way.
- **"Clear filter"**, which takes every entry about the column out of the filter and closes the menu — whichever editor wrote them, or none did, as with a predicate set in code. Disabled while the column is not filtered.
- **Cancel** and **OK**. The editor edits a draft, so nothing filters until OK applies it; Cancel drops it.

## Keyboard & pointer interactions

The menu is a dialog that holds a draft, so it keeps focus: tabbing out of it would drop the draft.

| Key or action                                                            | Does                                                                                          |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd>+<Kbd>ArrowDown</Kbd> on a focused header | Opens its filter menu.                                                                        |
| Opening it                                                               | Focus goes to its first control.                                                              |
| <Kbd>Tab</Kbd> / <Kbd>Shift</Kbd>+<Kbd>Tab</Kbd>                         | The next or previous control, wrapping round inside the menu. A disabled button is passed by. |
| <Kbd>Enter</Kbd>                                                         | In a field, applies, as OK does; on a button, presses it.                                     |
| <Kbd>Escape</Kbd>                                                        | Closes it without applying, giving focus back to the header.                                  |
| A click outside it, a scroll or a resize                                 | Closes it without applying.                                                                   |

<Kbd>Escape</Kbd> closes only the menu: it never reaches the grid, so the
selection stays.

## Commands and `onCommand`

"Filter…" and "Clear filter" are the [built-in commands](/docs/core/commands#built-in-commands) `filter.open` and `filter.clear`, shown only on the header of a column with a filter menu. The menu's sort entries and its "Clear filter" run the same commands, so a [command of your own](/docs/react/context-menu#commands-of-your-own) with one of their ids replaces it inside the menu too, and `onCommand` hears each one with the source `"filterMenu"`:

```tsx
<DataGrid
  columns={columns}
  dataSource={orders}
  filterableColumns
  onCommand={({ commandId, target, source }) => {
    // "filterMenu" for a sort entry or "Clear filter" chosen in the menu.
    track(commandId, source);
  }}
/>
```

## Messages

Every string the menu shows is a message — see [localization](/docs/react/localization):

| Key                 | Default                                                         |
| ------------------- | --------------------------------------------------------------- |
| `openFilter`        | "Filter…" — `filter.open`'s label.                              |
| `clearColumnFilter` | "Clear filter" — `filter.clear`'s label, and the menu's button. |
| `filterMenuLabel`   | "Name filter" — the dialog's accessible name, after its column. |
| `columnFiltered`    | "Filtered" — a filtered column's header's description.          |
| `applyFilter`       | "OK"                                                            |
| `cancelFilter`      | "Cancel"                                                        |

The theme's classes for it are listed under [filter menu](/docs/theme-tailwind#filter-menu), and the header's filter button under [header](/docs/theme-tailwind#header).
