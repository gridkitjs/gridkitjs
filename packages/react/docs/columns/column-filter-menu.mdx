title: "Column filter menu"
description: "A filter popup per column, opened from its header — its sort entries, its editor, and Clear filter, Cancel and OK — turned on with filterableColumns."
---

A column with a filter menu opens a small dialog below its header for filtering that column: the column's sort entries at the top, an editor for its filter, and buttons to clear the filter, cancel or apply. It edits the grid's one [filter](/docs/react/column-filtering), so the menu, the toolbar's search box, `setFilter` and a controlled `filter` always agree.

## Turning it on

```tsx
<DataGrid
  columns={[
    { field: "Id", filterable: false },
    { field: "Customer" },
    { field: "Amount", type: "number" },
  ]}
  dataSource={orders}
  sortableColumns
  filterableColumns
  contextMenu
/>
```

`filterableColumns` gives every column a filter menu unless the column's own `filterable` says otherwise; it is off by default, like `sortableColumns`. The filter applies either way: a column without a menu is still filtered by `defaultFilter`, `setFilter` or a search.

| Prop                | Type                      | Default | Description                                                                     |
| ------------------- | ------------------------- | ------- | ------------------------------------------------------------------------------- |
| `filterableColumns` | `boolean`                 | `false` | Whether columns get a filter menu, unless a column says otherwise.              |
| `column.filterable` | `boolean`                 |         | Per-column override of `filterableColumns`.                                     |
| `filterMenu`        | `GridFilterMenuOptions`   |         | How the grid's filter menus look — see [options](#options).                     |
| `column.filterMenu` | `ColumnFilterMenuOptions` |         | Per-column override of `filterMenu.ui`, and the operators its conditions offer. |

### Options

`filterMenu` sets every filter menu of the grid; a column's own `filterMenu` overrides it, setting by setting.

| Option                        | Type                        | Default         | Description                                                                                                                                                                   |
| ----------------------------- | --------------------------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `filterMenu.ui`               | `"simple" \| "excel"`       | `"simple"`      | Which editor the menu opens. Every editor edits the one filter, so switching keeps it. `"excel"` names the checklist editor, which is not drawn yet: it opens the simple one. |
| `filterMenu.showCounts`       | `boolean`                   | `false`         | For the checklist editor: whether each value shows how many rows hold it.                                                                                                     |
| `filterMenu.valueLimit`       | `number`                    | `10000`         | For the checklist editor: how many values it lists before asking for a search first.                                                                                          |
| `column.filterMenu.ui`        | `"simple" \| "excel"`       | `filterMenu.ui` | Which editor this column's menu opens.                                                                                                                                        |
| `column.filterMenu.operators` | `readonly FilterOperator[]` | by `type`       | The conditions this column offers, in order, in place of its type's — see [the simple editor](#the-simple-editor). `in` is dropped, since only a checklist picks values.      |

## Opening it

- **The header's filter button.** A filterable header shows a funnel at its end, beside the sort toggle — faint until the header is hovered or focused, and marked while the column is filtered. Pressing it opens the menu, and pressing it again closes it.
- **The keyboard.** <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd>+<Kbd>ArrowDown</Kbd> on a focused header opens it. The header's `aria-keyshortcuts` lists the key, as it does its others.
- **A header's context menu.** With [`contextMenu`](/docs/react/context-menu) on, a filterable header's menu lists "Filter…" after its sort entries, then "Clear filter", which clears the column's filter without opening anything — disabled while the column is not filtered.
- **The ref.** `openFilterMenu(columnId)` opens it, and returns whether it did: not for a column with no filter menu, nor a hidden one, which has no header to open below. `closeFilterMenu()` closes it, leaving the column chooser alone. `runCommand("filter.open", { area: "header", columnId })` opens it too, reporting to `onCommand` as the API's.

It opens below the header and gives focus back to it when it closes. Only one panel is open at a time: opening a filter menu replaces the column chooser, or another column's filter menu.

```tsx
const gridRef = useRef<DataGridApi<Order>>(null);

<DataGrid
  ref={gridRef}
  columns={columns}
  dataSource={orders}
  filterableColumns
/>;

<button onClick={() => gridRef.current?.openFilterMenu("Customer")}>
  Filter customers
</button>;
```

## The filtered state

While a column with a filter menu is filtered — by the menu, `setFilter`, a controlled `filter` or anything else naming the column — its header's filter button stays shown, in accent, and the header carries `aria-description="Filtered"`, so a screen reader says so as it reads the header. A search across every column marks none, and a column without a filter menu shows no filtered state, however it is filtered.

## What it shows

- **The column's sort entries** — "Sort ascending", "Sort descending" and "Clear sort", the header menu's own — while the column [sorts](/docs/react/column-sorting). Choosing one sorts the column and closes the menu; "Sort ascending" or "Sort descending" is pressed while the column sorts that way.
- **The editor**, for the column's filter — see [the simple editor](#the-simple-editor).
- **"Clear filter"**, which takes every entry about the column out of the filter and closes the menu — whichever editor wrote them, or none did, as with a predicate set in code. Disabled while the column is not filtered.
- **Cancel** and **OK**. The editor edits a draft, so nothing filters until OK applies it; Cancel drops it.

## The simple editor

One condition — an operator and a value — and an optional second, joined to the first by **And** or **Or**:

- **The operator** lists the conditions the column offers, in its type's words: "Before" and "After" on a date column where a number reads "Less than" and "Greater than".
- **The value** goes in a box made for the column's `type`: a number box, a date picker on a `"date"` column, a date-and-time picker on a `"dateTime"` or `"time"` one, a true/false choice on a `"boolean"` one, and a text box on the rest. "Between" takes two, From and To; "Is blank" and "Is not blank" take none.
- **The second condition** is optional: left empty, it is dropped.

| Column `type`                                      | Its conditions, by default                                                                                                        |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `"string"`, or none                                | Contains, Does not contain, Equals, Does not equal, Starts with, Ends with, Is blank, Is not blank                                |
| `"number"`, `"decimal"`, `"currency"`, `"percent"` | Equals, Does not equal, Greater than, Greater than or equal to, Less than, Less than or equal to, Between, Is blank, Is not blank |
| `"date"`                                           | Equals, Does not equal, Before, After, Between, Is blank, Is not blank                                                            |
| `"dateTime"`, `"time"`                             | Before, After, Between, Is blank, Is not blank — a moment seldom equals a typed minute to the millisecond                         |
| `"boolean"`                                        | Equals, Is blank, Is not blank                                                                                                    |

A column's `filterMenu.operators` lists its own instead — `{ field: "Amount", type: "number", filterMenu: { operators: ["gt", "lt", "between"] } }`.

OK, or <Kbd>Enter</Kbd>, applies the conditions in place of every entry about the column, keeping every other column's: one condition as one operator entry, two as a group with their combinator.

```ts
// "Score" between 10 and 25
[{ columnId: "score", operator: "between", value: [10, 25] }];

// "Name" contains "Ch" or starts with "Al"
[
  {
    combinator: "or",
    entries: [
      { columnId: "name", operator: "contains", value: "Ch" },
      { columnId: "name", operator: "startsWith", value: "Al" },
    ],
  },
];
```

Once the grid has drawn the rows the filter keeps, the live region announces how many of all the rows they are — "2 of 3 rows", the `filterResults` message — so a screen reader hears the result as focus returns to the header. A controlled `filter` that doesn't take the change announces nothing.

Opened again, the menu shows the conditions as they are applied, whatever applied them: the menu itself, `defaultFilter`, `setFilter` or a controlled `filter`. A condition set in code with an operator the column doesn't offer still shows, its operator listed for it.

- **A value that doesn't read** — a condition left without one, a number the box can't read, a date missing its year, a "Between" missing an end — keeps the menu open. The box is marked invalid, described by a message ("Enter a number"), and takes focus. OK on conditions left as they opened, with nothing typed in them, just closes the menu.
- **A filter the editor can't show** — a text query, a predicate, a group across columns, or a list of values — reads "Custom filter" above empty conditions. It stays as it is until conditions are applied in its place, or "Clear filter" takes it out.

## Keyboard & pointer interactions

The menu is a dialog that holds a draft, so it keeps focus: tabbing out of it would drop the draft.

| Key or action                                                            | Does                                                                                          |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd>+<Kbd>ArrowDown</Kbd> on a focused header | Opens its filter menu.                                                                        |
| Opening it                                                               | Focus goes to the first condition's value box — or its operator, when that takes no value.    |
| <Kbd>Tab</Kbd> / <Kbd>Shift</Kbd>+<Kbd>Tab</Kbd>                         | The next or previous control, wrapping round inside the menu. A disabled button is passed by. |
| <Kbd>Enter</Kbd>                                                         | In a box, a picker or a radio button, applies, as OK does; on a button, presses it.           |
| <Kbd>Escape</Kbd>                                                        | Closes it without applying, giving focus back to the header.                                  |
| A click outside it, a scroll or a resize                                 | Closes it without applying.                                                                   |

<Kbd>Escape</Kbd> closes only the menu: it never reaches the grid, so the
selection stays.

## Commands and `onCommand`

"Filter…" and "Clear filter" are the [built-in commands](/docs/core/commands#built-in-commands) `filter.open` and `filter.clear`, shown only on the header of a column with a filter menu. The menu's sort entries and its "Clear filter" run the same commands, so a [command of your own](/docs/react/context-menu#commands-of-your-own) with one of their ids replaces it inside the menu too, and `onCommand` hears each one with the source `"filterMenu"`:

```tsx
<DataGrid
  columns={columns}
  dataSource={orders}
  filterableColumns
  onCommand={({ commandId, target, source }) => {
    // "filterMenu" for a sort entry or "Clear filter" chosen in the menu.
    track(commandId, source);
  }}
/>
```

## Messages

Every string the menu shows is a message — see [localization](/docs/react/localization):

| Key                        | Default                                                                     |
| -------------------------- | --------------------------------------------------------------------------- |
| `openFilter`               | "Filter…" — `filter.open`'s label.                                          |
| `clearColumnFilter`        | "Clear filter" — `filter.clear`'s label, and the menu's button.             |
| `filterMenuLabel`          | "Name filter" — the dialog's accessible name, after its column.             |
| `columnFiltered`           | "Filtered" — a filtered column's header's description.                      |
| `applyFilter`              | "OK"                                                                        |
| `cancelFilter`             | "Cancel"                                                                    |
| `filterOperatorLabel`      | "Before" — a condition's operator, in its column type's words.              |
| `filterConditionLabel`     | "Condition 1" — a condition's accessible name.                              |
| `filterOperatorFieldLabel` | "Operator" — its operator picker's accessible name.                         |
| `filterValueLabel`         | "Value" — its value box's accessible name.                                  |
| `filterFromLabel`          | "From" — a "Between" condition's first box.                                 |
| `filterToLabel`            | "To" — its second box.                                                      |
| `filterCombinatorLabel`    | "Combine conditions" — the And/Or choice's accessible name.                 |
| `filterAnd`                | "And"                                                                       |
| `filterOr`                 | "Or"                                                                        |
| `filterValueInvalid`       | "Enter a number" — under a value that doesn't read, by the column's type.   |
| `customFilter`             | "Custom filter" — above the conditions, for a filter the editor can't show. |
| `filterResults`            | "2 of 3 rows" — announced once the rows an applied filter keeps are drawn.  |

The theme's classes for it are listed under [filter menu](/docs/theme-tailwind#filter-menu), and the header's filter button under [header](/docs/theme-tailwind#header).
