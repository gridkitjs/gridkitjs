---

A column with a filter menu opens a small dialog below its header for filtering that column: the column's sort entries at the top, an editor for its filter, and buttons to clear the filter, cancel or apply. It edits the grid's one [filter](/docs/react/column-filtering), so the menu, the toolbar's search box, `setFilter` and a controlled `filter` always agree.

Three things open it, each [described below](#opening-it): the funnel button in a filterable header, <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd>+<Kbd>ArrowDown</Kbd> on a focused header, and "Filter…" in a header's context menu. `<DataGrid {...excelFilter} />` turns the whole feature on in its Excel-style form — see [presets](#presets).

## Turning it on

```tsx
<DataGrid
  columns={[
    { field: "Id", filterable: false },
    { field: "Customer" },
    { field: "Amount", type: "number" },
  ]}
  dataSource={orders}
  sortableColumns
  filterableColumns
  contextMenu
/>
```

`filterableColumns` gives every column a filter menu unless the column's own `filterable` says otherwise; it is off by default, like `sortableColumns`. The filter applies either way: a column without a menu is still filtered by `defaultFilter`, `setFilter` or a search.

| Prop                | Type                      | Default | Description                                                                     |
| ------------------- | ------------------------- | ------- | ------------------------------------------------------------------------------- |
| `filterableColumns` | `boolean`                 | `false` | Whether columns get a filter menu, unless a column says otherwise.              |
| `column.filterable` | `boolean`                 |         | Per-column override of `filterableColumns`.                                     |
| `filterMenu`        | `GridFilterMenuOptions`   |         | How the grid's filter menus look — see [options](#options).                     |
| `column.filterMenu` | `ColumnFilterMenuOptions` |         | Per-column override of `filterMenu.ui`, and the operators its conditions offer. |

### Options

`filterMenu` sets every filter menu of the grid; a column's own `filterMenu` overrides it, setting by setting.

| Option                        | Type                        | Default         | Description                                                                                                                                                                   |
| ----------------------------- | --------------------------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `filterMenu.ui`               | `"simple" \| "excel"`       | `"simple"`      | Which editor the menu opens: [conditions](#the-simple-editor) or a [checklist of values](#the-excel-editor). Every editor edits the one filter, so switching keeps it intact. |
| `filterMenu.showCounts`       | `boolean`                   | `false`         | For the checklist editor: whether each value shows how many rows hold it.                                                                                                     |
| `filterMenu.valueLimit`       | `number`                    | `10000`         | For the checklist editor: how many values it lists before asking for a search first.                                                                                          |
| `column.filterMenu.ui`        | `"simple" \| "excel"`       | `filterMenu.ui` | Which editor this column's menu opens.                                                                                                                                        |
| `column.filterMenu.operators` | `readonly FilterOperator[]` | by `type`       | The conditions this column offers, in order, in place of its type's — see [the simple editor](#the-simple-editor). `in` is dropped, since only a checklist picks values.      |

## Opening it

- **The header's filter button.** A filterable header shows a funnel at its end, beside the sort toggle — faint until the header is hovered or focused, and marked while the column is filtered. Pressing it opens the menu, and pressing it again closes it.
- **The keyboard.** <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd>+<Kbd>ArrowDown</Kbd> on a focused header opens it. The header's `aria-keyshortcuts` lists the key, as it does its others.
- **A header's context menu.** With [`contextMenu`](/docs/react/context-menu) on, a filterable header's menu lists "Filter…" after its sort entries, then "Clear filter", which clears the column's filter without opening anything — disabled while the column is not filtered.
- **The ref.** `openFilterMenu(columnId)` opens it, and returns whether it did: not for a column with no filter menu, nor a hidden one, which has no header to open below. `closeFilterMenu()` closes it, leaving the column chooser alone. `runCommand("filter.open", { area: "header", columnId })` opens it too, reporting to `onCommand` as the API's.

It opens below the header and gives focus back to it when it closes. Only one panel is open at a time: opening a filter menu replaces the column chooser, or another column's filter menu.

```tsx
const gridRef = useRef<DataGridApi<Order>>(null);

<DataGrid
  ref={gridRef}
  columns={columns}
  dataSource={orders}
  filterableColumns
/>;

<button onClick={() => gridRef.current?.openFilterMenu("Customer")}>
  Filter customers
</button>;
```

## The filtered state

While a column with a filter menu is filtered — by the menu, `setFilter`, a controlled `filter` or anything else naming the column — its header's filter button stays shown, in accent, and the header carries `aria-description="Filtered"`, so a screen reader says so as it reads the header. A search across every column marks none, and a column without a filter menu shows no filtered state, however it is filtered.

## What it shows

- **The column's sort entries** — "Sort ascending", "Sort descending" and "Clear sort", the header menu's own — while the column [sorts](/docs/react/column-sorting). Choosing one sorts the column and closes the menu; "Sort ascending" or "Sort descending" is pressed while the column sorts that way.
- **The editor**, for the column's filter — [the simple editor](#the-simple-editor), or with `filterMenu.ui: "excel"` [the excel editor](#the-excel-editor).
- **"Clear filter"**, which takes every entry about the column out of the filter and closes the menu — whichever editor wrote them, or none did, as with a predicate set in code. Disabled while the column is not filtered.
- **Cancel** and **OK**. The editor edits a draft, so nothing filters until OK applies it; Cancel drops it.

## The simple editor

One condition — an operator and a value — and an optional second, joined to the first by **And** or **Or**:

- **The operator** lists the conditions the column offers, in its type's words: "Before" and "After" on a date column where a number reads "Less than" and "Greater than".
- **The value** goes in a box made for the column's `type`: a number box, a date picker on a `"date"` column, a date-and-time picker on a `"dateTime"` or `"time"` one, a true/false choice on a `"boolean"` one, and a text box on the rest. "Between" takes two, From and To; "Is blank" and "Is not blank" take none.
- **The second condition** is optional: left empty, it is dropped.

| Column `type`                                      | Its conditions, by default                                                                                                        |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `"string"`, or none                                | Contains, Does not contain, Equals, Does not equal, Starts with, Ends with, Is blank, Is not blank                                |
| `"number"`, `"decimal"`, `"currency"`, `"percent"` | Equals, Does not equal, Greater than, Greater than or equal to, Less than, Less than or equal to, Between, Is blank, Is not blank |
| `"date"`                                           | Equals, Does not equal, Before, After, Between, Is blank, Is not blank                                                            |
| `"dateTime"`, `"time"`                             | Before, After, Between, Is blank, Is not blank — a moment seldom equals a typed minute to the millisecond                         |
| `"boolean"`                                        | Equals, Is blank, Is not blank                                                                                                    |

A column's `filterMenu.operators` lists its own instead — `{ field: "Amount", type: "number", filterMenu: { operators: ["gt", "lt", "between"] } }`.

OK, or <Kbd>Enter</Kbd>, applies the conditions in place of every entry about the column, keeping every other column's: one condition as one operator entry, two as a group with their combinator.

```ts
// "Score" between 10 and 25
[{ kind: "operator", columnId: "score", operator: "between", value: [10, 25] }];

// "Name" contains "Ch" or starts with "Al"
[
  {
    kind: "group",
    combinator: "or",
    entries: [
      { kind: "operator", columnId: "name", operator: "contains", value: "Ch" },
      {
        kind: "operator",
        columnId: "name",
        operator: "startsWith",
        value: "Al",
      },
    ],
  },
];
```

Once the grid has drawn the rows the filter keeps, the live region announces how many of all the rows they are — "2 of 3 rows", the `filterResults` message, its counts in the grid's [`locale`](/docs/react/localization#counts) ("1,204 of 10,000 rows") — so a screen reader hears the result as focus returns to the header. A controlled `filter` that doesn't take the change announces nothing, then or once it takes the filter later.

Opened again, the menu shows the conditions as they are applied, whatever applied them: the menu itself, `defaultFilter`, `setFilter` or a controlled `filter`. A condition set in code with an operator the column doesn't offer still shows, its operator listed for it. The column's filter set in code while the menu is open, through `setFilter` or a controlled `filter`, shows in it at once in place of what was typed, as it would on opening the menu again; another column's leaves what was typed.

- **A value that doesn't read** — a condition left without one, a number the box can't read, a date missing its year, a "Between" missing an end — keeps the menu open. The box is marked invalid, described by a message ("Enter a number"), and takes focus. OK on conditions as they opened, with nothing typed in them (or something typed and taken out again), just closes the menu.
- **OK on the column's own conditions** changes nothing: the filter stays as it was written, a group or two top-level entries alike, and `onFilterChange` hears nothing. A day set in code as a string, `"2024-01-01"`, stays a string.
- **A filter the editor can't show** — a text query, a predicate, a group across columns, or a list of values — reads "Custom filter" above empty conditions. It stays as it is until conditions are applied in its place, or "Clear filter" takes it out.

## The excel editor

With `filterMenu.ui: "excel"` — the grid's, or a column's own — the menu lists the values the column holds, each with a checkbox, as a spreadsheet's filter does:

```tsx
<DataGrid
  columns={columns}
  dataSource={orders}
  filterableColumns
  filterMenu={{ ui: "excel", showCounts: true }}
/>
```

- **The values** are the column's distinct values, in the order the column sorts, labelled as its cells print them — a date as the column formats it, a boolean in the `booleanTrue` and `booleanFalse` words. With `showCounts`, each shows how many rows hold it. Blank cells — `null`, `undefined` or `""` — are one item of their own, "(Blanks)", last.
- **They cascade.** The list holds the values of the rows the _other_ columns' filters keep, so with "Region" filtered to "North", "Customer" lists only the customers in the north. A column's own filter never hides its values: the ones it leaves out stay listed, to be checked again.
- **The search box** narrows the list to the values whose label holds what is typed, ignoring case.
- **"Select all"** checks every value the search shows, or unchecks them once all are — "(Blanks)" too while nothing is searched. It is a native checkbox, shown mixed while only some are checked.
- **A long list** draws only the values near its scroll position, so a column of thousands of values opens as quickly as one of ten. Past `filterMenu.valueLimit` values — 10,000 by default — it lists none until something is searched ("Type to search 12,000 values"), and a search matching more lists the first of them, saying how many it left out ("250 more, refine the search"). "Select all" still covers every value meanwhile.
- **"Text filters"** — "Number filters", "Date filters" or "Boolean filters", by the column's `type` — sits above the search box and opens a menu of the conditions the column offers, the simple editor's, beside the filter menu. Choosing one shows [the simple editor](#the-simple-editor) in place of the checklist, its first condition at the one chosen, under "Back to values", which brings the checklist back as it was left. A column whose `filterMenu.operators` is empty offers no menu.

OK, or <Kbd>Enter</Kbd>, applies the checked values in place of every entry about the column, keeping every other column's. Every value checked is no filter at all; anything less is one `in` entry holding the values checked, OR-ed with "is blank" while "(Blanks)" stays checked:

```ts
// "Name": Alice and Bravo checked
[
  {
    kind: "operator",
    columnId: "name",
    operator: "in",
    value: ["Alice", "Bravo"],
  },
];

// "Joined": one day and the blanks checked
[
  {
    kind: "group",
    combinator: "or",
    entries: [
      {
        kind: "operator",
        columnId: "joined",
        operator: "in",
        value: [new Date(2024, 4, 20)],
      },
      { kind: "operator", columnId: "joined", operator: "isEmpty" },
    ],
  },
];
```

The `in` entry holds the values checked rather than the ones left out, so a value that turns up later, in a new row, stays filtered out until it is checked. The rows the filter keeps are announced as [the simple editor's](#the-simple-editor) are.

With a condition chosen from "Text filters", OK applies the conditions instead, as the simple editor does — in place of the values checked, since a column is filtered by its values or by conditions, never both, as in Excel.

Opened again, the menu shows the values checked as they are applied, whatever applied them. The column's filter set in code while the menu is open shows in it at once in place of what was checked, as in the simple editor.

- **Conditions**, as the simple editor or `setFilter` writes them, open with every value checked under "Filtered by condition", the "Text filters" button ticked and the operators they use checked in its menu — choosing one opens the conditions as applied, the first at that operator, its value kept. **A filter the editor can't show** — a text query, a predicate, a group across columns — opens under "Custom filter". Either stays as it is until the values checked differ from those it opened with, or a condition is applied, replacing it, or "Clear filter" takes it out.
- **OK on checks as they opened**, whatever was searched, just closes the menu. A value unchecked and checked again, or "Select all" pressed twice, leaves the checks as they opened.

### Switching editors

`filterMenu.ui` can change at any time — from a toggle in your app, say — and every filter stays as it is, since both editors edit the one filter. Each opens on as much of it as it can show: conditions in the simple editor, or through the excel editor's "Text filters" menu; checked values in the excel editor, which the simple editor reads as "Custom filter". A filter set in code — `defaultFilter`, `setFilter` or a controlled `filter` — shows in whichever editor is on.

```tsx
const [ui, setUi] = useState<"simple" | "excel">("simple");

<button onClick={() => setUi(ui === "simple" ? "excel" : "simple")}>
  Switch filter editor
</button>;
<DataGrid
  columns={columns}
  dataSource={orders}
  filterableColumns
  filterMenu={{ ui }}
/>;
```

## Presets

`excelFilter` is the options for the excel editor as one plain value — `{ filterableColumns: true, filterMenu: { ui: "excel", showCounts: true } }` — so a grid takes the whole feature in a spread:

```tsx
import { DataGrid, excelFilter } from "@gridkitjs/react";

<DataGrid {...excelFilter} columns={columns} dataSource={orders} />;
```

A prop written after the spread overrides the preset, and one written before it is overridden by it. `filterMenu` is replaced whole, not merged setting by setting, so `filterMenu={{ ui: "simple" }}` after the spread brings the simple editor back and also drops the counts. To change one setting and keep the rest, spread the preset's own:

```tsx
<DataGrid {...excelFilter} filterMenu={{ ...excelFilter.filterMenu, ui }} />
```

The preset is core's, with the same names in every renderer — see [filtering](/docs/core/filtering#presets).

## Keyboard & pointer interactions

The menu is a dialog that holds a draft, so it keeps focus: tabbing out of it would drop the draft.

| Key or action                                                            | Does                                                                                          |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd>+<Kbd>ArrowDown</Kbd> on a focused header | Opens its filter menu.                                                                        |
| Opening it                                                               | Focus goes to the first condition's value box — or its operator, when that takes no value.    |
| Opening the excel editor                                                 | Focus goes to its search box.                                                                 |
| <Kbd>Tab</Kbd> / <Kbd>Shift</Kbd>+<Kbd>Tab</Kbd>                         | The next or previous control, wrapping round inside the menu. A disabled button is passed by. |
| <Kbd>ArrowDown</Kbd> / <Kbd>ArrowUp</Kbd> in the checklist               | The next or previous value. The checklist is one stop for <Kbd>Tab</Kbd>.                     |
| <Kbd>Home</Kbd> / <Kbd>End</Kbd> in the checklist                        | The first or last value, however long the list.                                               |
| <Kbd>PageDown</Kbd> / <Kbd>PageUp</Kbd> in the checklist                 | As many values down or up as the list shows at once.                                          |
| <Kbd>Space</Kbd> in the checklist, or a click on a value                 | Checks or unchecks the value.                                                                 |
| <Kbd>Enter</Kbd> or <Kbd>ArrowDown</Kbd> on "Text filters"               | Opens its menu of conditions on the first; <Kbd>ArrowUp</Kbd> on the last.                    |
| <Kbd>ArrowDown</Kbd> / <Kbd>ArrowUp</Kbd> in that menu                   | The next or previous condition. <Kbd>Enter</Kbd> chooses it, in place of the checklist.       |
| <Kbd>Escape</Kbd> or <Kbd>Tab</Kbd> in that menu                         | Closes only the menu, giving focus back to "Text filters".                                    |
| <Kbd>Enter</Kbd>                                                         | Anywhere but on a button — a box, a picker, a checkbox, the checklist — applies, as OK does.  |
| <Kbd>Escape</Kbd>                                                        | Closes it without applying, giving focus back to the header.                                  |
| A click outside it, a scroll or a resize                                 | Closes it without applying.                                                                   |

<Kbd>Escape</Kbd> closes only the menu: it never reaches the grid, so the
selection stays.

## Commands and `onCommand`

"Filter…" and "Clear filter" are the [built-in commands](/docs/core/commands#built-in-commands) `filter.open` and `filter.clear`, shown only on the header of a column with a filter menu. The menu's sort entries and its "Clear filter" run the same commands, so a [command of your own](/docs/react/context-menu#commands-of-your-own) with one of their ids replaces it inside the menu too, and `onCommand` hears each one with the source `"filterMenu"`:

```tsx
<DataGrid
  columns={columns}
  dataSource={orders}
  filterableColumns
  onCommand={({ commandId, target, source }) => {
    // "filterMenu" for a sort entry or "Clear filter" chosen in the menu.
    track(commandId, source);
  }}
/>
```
