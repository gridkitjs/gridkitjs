title: "DataGrid"

---

DataGrid takes a set of columns and a data source and renders a grid. Resizing, reordering, and selection are all opt-in — enable them per grid with resizableColumns, reorderableColumns, and selectable, or per column via each column's own resizable and reorderable fields.

## Resizable, reorderable columns

<LiveExampleFrame title="DataGrid">
  <DataGridResizeReorderExample />
</LiveExampleFrame>

```ts
import { useState } from "react";
import { defineColumnsFromRows } from "@gridkitjs/core";
import {
  DataGrid,
  type ColumnDefinition,
  type ResizeMode,
} from "@gridkitjs/react";

const columns: readonly ColumnDefinition<Row>[] = [
  ...defineColumnsFromRows(rows),
  {
    field: "Cost",
    id: "Cost.currency",
    type: "currency",
    headerTemplate: <span className="italic">Cost</span>,
    cellTemplate: ({ value, row }) => (
      <span className={row.Cost > 500 ? "font-semibold text-red-600" : ""}>
        {currency.format(Number(value))}
      </span>
    ),
  },
];

const [resizeMode, setResizeMode] = useState<ResizeMode>("fit");

<DataGrid
  columns={columns}
  dataSource={rows}
  borders="all"
  resizableColumns
  reorderableColumns
  resizeMode={resizeMode}
/>;
```

## Row props

`getRowProps` gives each data row a class and `data-*` attributes worked out from the row — a class for your stylesheet to target, an attribute for a test or a script to find the row by. It takes the `ResolvedRow<Row>` and returns `{ className?, attributes? }`; group headers and summary rows are not passed to it. There is no inline `style`: styling belongs to the stylesheet, which the class already reaches.

```ts
<DataGrid
  columns={columns}
  dataSource={rows}
  getRowId={(row) => String(row.Id)}
  getRowProps={({ row }) => ({
    className: row.dueDate < today ? "is-overdue" : undefined,
    attributes: { "data-status": row.status },
  })}
/>
```

It runs for each data row as the row renders, so keep it cheap. A row whose class and attributes read the same as last time is not redrawn for them, so an inline arrow returning a fresh object every time is fine.

Every data row also carries `data-gridkit-row-id`, its id as `getRowId` resolves it, whether or not `getRowProps` is given — `tr[data-gridkit-row-id="42"]` finds a row however it has been sorted or paged. The grid's own `data-gridkit-*` attributes win over one of the same name from `getRowProps`.

## Scrollable layout

Set `height` to bound the row area to a fixed size, independently scrollable, while the group-by bar, header, footer, and pager stay outside it and always visible:

```tsx
<DataGrid columns={columns} dataSource={rows} height={400} />
```

Under the hood, the header, the rows, and (when `aggregates` is active) the grand-total footer each render as their own `<table>` — `.gridkit-data-grid-header`, `.gridkit-data-grid-body` (the one `height` applies to), and `.gridkit-data-grid-footer` — rather than sharing one. That's what keeps the header and footer out of the region that scrolls: they're never inside it to begin with, so there's nothing to pin in place with `position: sticky`. A consumer who wants a divider or shadow at the seam adds their own CSS targeting one of those classes directly, for example:

```css
.gridkit-data-grid-header {
  box-shadow: 0 1px 0 var(--gridkit-line);
}
```

## Keyboard & pointer interactions

- Drag a header's trailing edge to resize; double-click it to size the column to its content.
- With the trailing edge focused, <Kbd>Alt</Kbd>+<Kbd>ArrowLeft</Kbd> / <Kbd>Alt</Kbd>+<Kbd>ArrowRight</Kbd> nudge the width; <Kbd>Escape</Kbd> cancels an in-progress resize.
- Drag a header to reorder columns.
- With a header focused, <Kbd>Ctrl</Kbd>+<Kbd>ArrowLeft</Kbd> / <Kbd>Ctrl</Kbd>+<Kbd>ArrowRight</Kbd> reorders it via keyboard; <Kbd>Escape</Kbd> cancels an in-progress drag.
- Click a row, column, or cell to select it; <Kbd>Ctrl</Kbd>+click toggles, <Kbd>Shift</Kbd>+click takes a range. Under `selectable.toggleOnClick` a plain click toggles a row too.
- <Kbd>Ctrl</Kbd>+<Kbd>A</Kbd> selects every row; <Kbd>Escape</Kbd> clears every
  selection.
- Click a groupable header's group icon, or focus the header and press <Kbd>Alt</Kbd>+<Kbd>ArrowDown</Kbd>, to add or remove it from the group-by stack — or drag the header into the group-by bar, for a column that sets `groupByDraggable`.
- Drag a chip in the group-by bar to reorder the stack; with a chip focused, <Kbd>Ctrl</Kbd>+<Kbd>ArrowLeft</Kbd> / <Kbd>Ctrl</Kbd>+<Kbd>ArrowRight</Kbd> moves it via keyboard.
- Click a group header, or focus it and press <Kbd>Space</Kbd>/<Kbd>Enter</Kbd>, to expand or collapse it.
- Under `contextMenu`, right-click a header, cell or group row, or focus it and press <Kbd>Shift</Kbd>+<Kbd>F10</Kbd> or <Kbd>ContextMenu</Kbd>, to open its menu.

These keys act only when pressed inside the grid itself. A popover or menu that a template portals into `document.body` still sits inside the grid in React's tree, and React bubbles its events through the grid's handlers — but the grid ignores them, so <Kbd>Escape</Kbd> in it leaves the selection alone and <Kbd>Ctrl</Kbd>+<Kbd>A</Kbd> in its text box selects the text.
