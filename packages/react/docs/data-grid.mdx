`DataGrid` takes column definitions and a data source and renders an accessible grid. Every feature is opt-in: turn it on for the whole grid with a prop such as `resizableColumns`, `reorderableColumns` or `selectable`, or per column through the column's own field, such as `resizable` or `reorderable`.

## A minimal grid

```tsx title="App.tsx"
import { DataGrid, type ColumnDefinition } from "@gridkitjs/react";

interface Task {
  id: number;
  title: string;
  owner: string;
  estimate: number;
}

const tasks: Task[] = [
  { id: 1, title: "Write the release notes", owner: "Ana", estimate: 2 },
  { id: 2, title: "Review the pull request", owner: "Marko", estimate: 1 },
  { id: 3, title: "Fix the flaky test", owner: "Ivana", estimate: 3 },
];

const columns: readonly ColumnDefinition<Task>[] = [
  { field: "title", header: "Task" },
  { field: "owner", header: "Owner" },
  { field: "estimate", header: "Estimate (h)", type: "number" },
];

export default function App() {
  return (
    <DataGrid
      columns={columns}
      dataSource={tasks}
      getRowId={(row) => String(row.id)}
      label="Tasks"
    />
  );
}
```

See the [quick start](/docs/react) for installing the package and importing its stylesheet.

## Row props

`getRowProps` gives each data row a class and `data-*` attributes worked out from the row — a class for your stylesheet to target, an attribute for a test or a script to find the row by. It takes the `ResolvedRow<Row>` and returns `{ className?, attributes? }`; group headers and summary rows are not passed to it. There is no inline `style`: styling belongs to the stylesheet, which the class already reaches.

```tsx title="App.tsx"
import { DataGrid, type ColumnDefinition } from "@gridkitjs/react";

interface Invoice {
  id: number;
  customer: string;
  status: "paid" | "open";
  dueDate: string; // ISO date, e.g. "2026-03-01"
}

const invoices: Invoice[] = [
  { id: 1, customer: "Alder & Co", status: "paid", dueDate: "2026-01-15" },
  { id: 2, customer: "Birchwood Ltd", status: "open", dueDate: "2026-02-01" },
  { id: 3, customer: "Cedar Supplies", status: "open", dueDate: "2099-12-31" },
];

const columns: readonly ColumnDefinition<Invoice>[] = [
  { field: "customer", header: "Customer" },
  { field: "status", header: "Status" },
  { field: "dueDate", header: "Due" },
];

const today = new Date().toISOString().slice(0, 10);

export default function App() {
  return (
    <DataGrid
      columns={columns}
      dataSource={invoices}
      getRowId={(row) => String(row.id)}
      getRowProps={({ row }) => ({
        className:
          row.status === "open" && row.dueDate < today
            ? "is-overdue"
            : undefined,
        attributes: { "data-status": row.status },
      })}
    />
  );
}
```

```css title="index.css"
.gridkit-grid-row.is-overdue {
  color: oklch(0.55 0.2 25);
}
```

It runs for each data row as the row renders, so keep it cheap. A row whose class and attributes read the same as last time is not redrawn for them, so an inline arrow returning a fresh object every time is fine.

Every data row also carries `data-gridkit-row-id`, its id as `getRowId` resolves it, whether or not `getRowProps` is given — `tr[data-gridkit-row-id="42"]` finds a row however it has been sorted or paged. The grid's own `data-gridkit-*` attributes win over one of the same name from `getRowProps`.

## An empty grid

When there are no rows to show, the grid says so under its header: "No rows match the current filter" while a filter or the toolbar's search is active, since the rows may only be hidden, and "No rows to show" otherwise. The two are the `noMatchingRows` and `noRows` messages, so a translation changes them (see [localization](/docs/react/localization)). A grid with no columns shows neither, and neither shows while [infinite scroll](/docs/react/infinite-scroll) can still load more rows: its loading row stands in for them.

`emptyTemplate` replaces the message's content with your own. It is handed an `EmptyTemplateContext`, `{ filtered: boolean }`, whether a filter or search is active:

```tsx title="App.tsx"
import { useState } from "react";
import { DataGrid, type ColumnDefinition } from "@gridkitjs/react";

interface Task {
  id: number;
  title: string;
}

const columns: readonly ColumnDefinition<Task>[] = [
  { field: "id", header: "#", type: "number", width: 80 },
  { field: "title", header: "Title" },
];

export default function App() {
  const [tasks, setTasks] = useState<Task[]>([]);

  return (
    <DataGrid
      columns={columns}
      dataSource={tasks}
      getRowId={(row) => String(row.id)}
      label="Tasks"
      toolbar={{ items: ["search", "filter.clearAll"] }}
      emptyTemplate={({ filtered }) =>
        filtered ? (
          "No task matches your search."
        ) : (
          <button
            type="button"
            onClick={() => {
              setTasks([{ id: 1, title: "Write the first task" }]);
            }}
          >
            Add a task
          </button>
        )
      }
    />
  );
}
```

A template returning `null` leaves the body blank. A button or link in the template is reached by <Kbd>Tab</Kbd> like any other on the page; the grid's own keyboard navigation skips the message, which takes no focus of its own.

The message is one row spanning every column, `tr.gridkit-grid-empty-row` with its `div.gridkit-grid-empty-content`, so a screen reader reading the grid reaches it, but it is not a data row: `aria-rowcount` leaves it out, and selection, navigation and the row events never address it. The stylesheet centres it in the part of the grid in view, however far a wide grid is scrolled sideways.

## A loading grid

`loading` tells the grid your app is fetching rows. While it is `true`, a translucent overlay covers the body with the `loading` message, "Loading…", and the rows already drawn stay where they are underneath it, so the grid does not jump when the new rows arrive. The header, toolbar and pager are not covered. The grid never sets `loading` itself and never fetches: set it while your request is in flight, and clear it when the rows arrive or the request fails.

```tsx title="App.tsx"
import { useEffect, useState } from "react";
import {
  DataGrid,
  type ColumnDefinition,
  type ColumnSortState,
} from "@gridkitjs/react";

interface Order {
  id: number;
  customer: string;
}

const columns: readonly ColumnDefinition<Order>[] = [
  { field: "id", header: "#", type: "number", width: 80 },
  { field: "customer", header: "Customer" },
];

async function fetchOrders(sort: ColumnSortState): Promise<Order[]> {
  const order = sort[0]?.direction ?? "asc";
  const response = await fetch(`/api/orders?order=${order}`);
  return (await response.json()) as Order[];
}

export default function App() {
  const [orders, setOrders] = useState<Order[]>([]);
  const [sort, setSort] = useState<ColumnSortState>([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    let current = true;
    fetchOrders(sort)
      .then((rows) => {
        if (current) setOrders(rows);
      })
      .catch(() => undefined)
      .finally(() => {
        if (current) setLoading(false);
      });
    return () => {
      current = false;
    };
  }, [sort]);

  return (
    <DataGrid
      columns={columns}
      dataSource={orders}
      getRowId={(row) => String(row.id)}
      label="Orders"
      sortableColumns
      columnSort={sort}
      onColumnSortChange={(event) => {
        setSort(event.sort);
        setLoading(true);
      }}
      loading={loading}
    />
  );
}
```

While loading:

- The overlay takes pointer input on the body, so a click on a row underneath selects nothing and fires no row event. Keyboard focus stays where it was, and nothing in the header, toolbar or pager is disabled: a user can still sort, filter or change page, and your app decides what a change made mid-request does.
- The [empty message](#an-empty-grid) waits: a grid loading with no rows shows the overlay in its place, and the message shows only if the rows are still none once `loading` is `false`.
- The grid carries `aria-busy="true"`, and the `loading` message is announced once, as loading starts. Nothing is announced as it ends; the rows that arrive are described by the grid's usual announcements. See [accessibility](/docs/react/accessibility).

`loadingTemplate` replaces the overlay's message with your own, a spinner for example: `loadingTemplate={() => <Spinner />}`. It is unrelated to `infiniteScroll.loadingTemplate`, which draws the row [infinite scroll](/docs/react/infinite-scroll) shows while it loads more; both can show at once. The grid adds no delay before the overlay shows; to avoid a flash on a fast request, set `loading` a moment after the request starts.

The overlay is `div.gridkit-grid-loading-overlay` with its `div.gridkit-grid-loading-overlay-content`, a row the grid owns but not a data row: `aria-rowcount` leaves it out, and navigation never moves to it. The stylesheet keeps the message centred in the rows in view, however the body is scrolled. See [class names](/docs/theme-tailwind/class-names).

## Scrollable layout

Set `height` to bound the row area to a fixed size. The rows scroll while the group-by bar, header, footer, and pager stay in view:

```tsx title="App.tsx"
import { DataGrid, type ColumnDefinition } from "@gridkitjs/react";

interface Reading {
  id: number;
  sensor: string;
  celsius: number;
}

const readings: Reading[] = Array.from({ length: 200 }, (_, index) => ({
  id: index + 1,
  sensor: `Sensor ${String((index % 8) + 1)}`,
  celsius: 18 + ((index * 7) % 90) / 10,
}));

const columns: readonly ColumnDefinition<Reading>[] = [
  { field: "id", header: "#", type: "number", width: 80 },
  { field: "sensor", header: "Sensor" },
  { field: "celsius", header: "°C", type: "decimal" },
];

export default function App() {
  return (
    <DataGrid
      columns={columns}
      dataSource={readings}
      getRowId={(row) => String(row.id)}
      label="Readings"
      height={400}
    />
  );
}
```

Under the hood, the header, the rows, and (when `aggregates` is active) the grand-total footer each render as their own `<table>` rather than sharing one. All three carry `.gridkit-data-grid`; the header adds `.gridkit-data-grid-header`, the footer `.gridkit-data-grid-footer`, and the rows' table sits inside `div.gridkit-data-grid-body`. All three sit in `div.gridkit-data-grid-tables`, the one element that scrolls, both up and down and sideways. The header and footer stick to its top and bottom (`position: sticky`), so they stay in view while the rows scroll under them, and since one element scrolls all three sideways, the column titles stay over their columns however the scroll starts: a wheel or trackpad, a swipe, or focus moving to a column out of view. `height` is the rows' height alone: the scrolling element grows by the header's and footer's. Its vertical scrollbar sits at the grid's visible edge, wherever it is scrolled sideways. The toolbar, the group-by bar and the pager sit outside it and stay where they are. A consumer who wants a divider or shadow at the seam adds their own CSS targeting one of those classes directly, for example:

```css
.gridkit-data-grid-header {
  box-shadow: 0 1px 0 var(--gridkit-line);
}
```

Every class the grid renders starts with `gridkit-`, and states are `is-*` classes beside them. [Class names](/docs/theme-tailwind/class-names) lists them all, with the `data-gridkit-*` attributes a test or a script can find rows, cells and columns by.

## Server rendering

`DataGrid` renders on the server (for example, prerendered by a Next.js App Router page) and hydrates on the client without a mismatch, so it needs no client-only wrapper. The server draws the grid's initial state from its props; anything that needs the browser (measuring the grid's width under `resizeMode="fit"`, the `virtualized` row window, a `use*State` hook reading the grid's `ref`) settles once the grid has hydrated. Until then, a hook such as `usePaginationState` reads its documented pre-mount value.

## Keyboard & pointer interactions

- Drag a header's trailing edge to resize; double-click it to size the column to its content.
- With a resizable header focused, <Kbd>Alt</Kbd>+<Kbd>ArrowLeft</Kbd> / <Kbd>Alt</Kbd>+<Kbd>ArrowRight</Kbd> nudge the width and <Kbd>Alt</Kbd>+<Kbd>Enter</Kbd> sizes the column to its content; <Kbd>Escape</Kbd> cancels an in-progress resize.
- Click a sortable header's sort toggle, or focus the header and press <Kbd>Alt</Kbd>+<Kbd>ArrowUp</Kbd>, to cycle its sort; <Kbd>Shift</Kbd>+click or <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd>+<Kbd>ArrowUp</Kbd> stacks it into the sort instead.
- Drag a header to reorder columns.
- With a header focused, <Kbd>Ctrl</Kbd>+<Kbd>ArrowLeft</Kbd> / <Kbd>Ctrl</Kbd>+<Kbd>ArrowRight</Kbd> reorders it via keyboard; <Kbd>Escape</Kbd> cancels an in-progress drag.
- Click a row, column, or cell to select it; <Kbd>Ctrl</Kbd>+click toggles, <Kbd>Shift</Kbd>+click takes a range. Under `selectable.toggleOnClick` a plain click toggles a row too.
- Under `selectable.rows: "multiple"`, <Kbd>Ctrl</Kbd>+<Kbd>A</Kbd> selects every data row on the current page; <Kbd>Escape</Kbd> clears every
  selection.
- Click a groupable header's group icon, or focus the header and press <Kbd>Alt</Kbd>+<Kbd>ArrowDown</Kbd>, to add or remove it from the group-by stack — or drag the header into the group-by bar, for a column that sets `groupByDraggable`.
- Click a filterable header's filter button, or focus the header and press <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd>+<Kbd>ArrowDown</Kbd>, to open its [filter menu](/docs/react/column-filter-menu).
- Drag a chip in the group-by bar to reorder the stack; with a chip focused, <Kbd>Ctrl</Kbd>+<Kbd>ArrowLeft</Kbd> / <Kbd>Ctrl</Kbd>+<Kbd>ArrowRight</Kbd> moves it via keyboard.
- Click a group header, or focus it and press <Kbd>Space</Kbd>/<Kbd>Enter</Kbd>, to expand or collapse it.
- Under `contextMenu`, right-click a header, cell or group row, or focus it and press <Kbd>Shift</Kbd>+<Kbd>F10</Kbd> or <Kbd>ContextMenu</Kbd>, to open its menu.
- Under `toolbar`, <Kbd>Tab</Kbd> to the toolbar and move between its controls with <Kbd>ArrowLeft</Kbd> / <Kbd>ArrowRight</Kbd>.

These keys act only when pressed inside the grid itself. A popover or menu that a template portals into `document.body` still sits inside the grid in React's tree, and React bubbles its events through the grid's handlers — but the grid ignores them, so <Kbd>Escape</Kbd> in it leaves the selection alone and <Kbd>Ctrl</Kbd>+<Kbd>A</Kbd> in its text box selects the text.

## Touch and small screens

The grid listens to pointer events, which a finger fires as a mouse does, so every pointer interaction above works on a phone or tablet, with the same grid and no separate mobile layout:

- Tap a row, column or cell to select it, and a header's sort, filter or group toggle to use it. A tap is a plain click: with no <Kbd>Ctrl</Kbd> or <Kbd>Shift</Kbd> to hold, `selectable.toggleOnClick` is how a tap adds a row to a selection.
- Under `contextMenu`, touch and hold a header, cell or group row for half a second to open its menu; tap outside it to close it.
- Drag a header's trailing edge to resize its column, and drag a reorderable header to move it.
- Swipe the rows, or a header that does not reorder, to scroll the grid sideways.
- The filter menu, the column chooser and the menus fit a phone's width, and the toolbar moves what does not fit into its More menu.

The [theme](/docs/theme-tailwind) adapts the header to a touch screen. Where the screen cannot hover, the sort, filter and group toggles show at rest rather than on hover; with a coarse pointer, each toggle and the resize handle take a 24 by 24 pixel target, the toggles sit side by side, and the label is cut short before them.

Limits:

- A drag that starts on a reorderable header, or on one that drags into the group-by bar, moves the column rather than scrolling the grid. Swipe the rows to scroll instead.
- There are no pinch, pull-to-refresh or swipe-to-act gestures.
