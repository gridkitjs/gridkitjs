---
title: "Events"
description: "The callbacks DataGrid fires as a user resizes, reorders, and selects."
---

Every interaction reports through a callback prop rather than a ref or an event you have to subscribe to — and so does every change made through the [imperative handle](/docs/react/imperative-handle)'s setters and `restoreState`, with the same payload, so one callback sees every change to its slice. A setter whose value equals the current one fires nothing. Resizing, reordering, and sorting fire one each; selection fires thirteen, one per row, column, and cell transition plus a whole-selection change to persist from.

## Resizing, reordering & sorting

| Prop                       | Type                                      | Description                                                                                                                                                                                                                               |
| -------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `onColumnResize`           | `(event: ColumnResizeEvent) => void`      | Fires continuously with phase "move" while dragging, once with "end" on release — the one to persist. Auto-fit does not call it.                                                                                                          |
| `onColumnOrderChange`      | `(event: ColumnOrderEvent) => void`       | Fires once when the user drops a column somewhere new. A drop that leaves the order unchanged does not call it.                                                                                                                           |
| `onColumnVisibilityChange` | `(event: ColumnVisibilityEvent) => void`  | Fires once per `showColumns`/`hideColumns` call that changes something, with every column it touched (`columnIds`) and the whole `visibility` state to persist. See [column visibility](/docs/react/column-definition#column-visibility). |
| `onColumnSortChange`       | `(event: ColumnSortEvent) => void`        | Fires once when the user changes the sort — a toggle, a stack, or a clear back to "none".                                                                                                                                                 |
| `onGroupByChange`          | `(event: GroupByEvent) => void`           | Fires once when the user adds, removes, or reorders a group-by level.                                                                                                                                                                     |
| `onGroupExpansionChange`   | `(event: GroupExpansionEvent) => void`    | Fires once when the user expands or collapses a group, or every group at once.                                                                                                                                                            |
| `onFilterChange`           | `(event: FilterChangeEvent<Row>) => void` | Fires once per filter change — today a `setFilter` call on the ref — with the whole `filter` to persist. See [column filtering](/docs/react/column-filtering).                                                                            |

## Row clicks

| Prop               | Type                                    | Description                                                                                                                                   |
| ------------------ | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `onRowClick`       | `(event: RowPointerEvent<Row>) => void` | Fires on every click on a data row, after the click has changed the selection, so a handler reading it sees the new one.                      |
| `onRowDoubleClick` | `(event: RowPointerEvent<Row>) => void` | Fires once per double-click on a data row — the usual "open this record" gesture. Its two clicks still fire `onRowClick` and select as usual. |

Neither fires for a group header or a group's summary row; a click there expands or collapses the group. `RowPointerEvent<Row>` carries no DOM event, so a handler reads the same payload whichever renderer drew the row:

| Field      | Type                                             | Description                                                                            |
| ---------- | ------------------------------------------------ | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `row`      | `ResolvedRow<Row>`                               | The row clicked — its `rowId`, the `row` itself, and its position.                     |
| `columnId` | `string                                          | null`                                                                                  | The column of the cell clicked, or `null` when the pointer was on no cell. |
| `native`   | `{ ctrlKey, metaKey, shiftKey, altKey, button }` | The modifiers held and the button pressed, numbered as `MouseEvent.button` numbers it. |

```ts
<DataGrid
  columns={columns}
  dataSource={rows}
  getRowId={(row) => String(row.Id)}
  onRowDoubleClick={({ row }) => openRecord(row.row)}
/>
```

## Commands and the context menu

| Prop                      | Type                                          | Description                                                                                                                                                                                                                                                      |
| ------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `onCommand`               | `(event: GridCommandEvent) => void`           | Fires after a command or an inline menu item runs — from a menu, the toolbar, or the ref's `runCommand` — with `{ commandId, target, source }`. One that did not run is not reported. See [commands of your own](/docs/react/context-menu#commands-of-your-own). |
| `onContextMenuOpenChange` | `(event: ContextMenuOpenChangeEvent) => void` | Fires as the context menu opens or closes, with `{ open, target }` — however it was opened or closed. A menu opened in place of another reports that one closing first. See [open state](/docs/react/context-menu#open-state).                                   |

## Selection

| Prop                                                                                                | Type                                        | Description                                                                                                                               |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `onRowSelect / onRowsSelect`                                                                        | `(event) => void`                           | Once per row newly selected, and once per interaction with every row it selected — a range selects many rows but fires onRowsSelect once. |
| `onRowDeselect / onRowsDeselect`                                                                    | `(event) => void`                           | The deselecting counterpart of each, above.                                                                                               |
| `onRowSelectionChange`                                                                              | `(event: RowSelectionChangeEvent) => void`  | Once per change with what it added, removed, and everything selected after.                                                               |
| `onColumnSelect / onColumnsSelect / onColumnDeselect / onColumnsDeselect / onColumnSelectionChange` | `(event) => void`                           | The same five events, for column selection.                                                                                               |
| `onCellSelect / onCellDeselect`                                                                     | `(event: CellSelectEvent) => void`          | Once for the cell selected, once for the cell deselected.                                                                                 |
| `onCellSelectionChange`                                                                             | `(event: CellSelectionChangeEvent) => void` | Once per change with what was selected and deselected — one interaction can fill both, since moving between cells does so at once.        |

Every payload's fields are broken down where its feature lives, rather than repeated here: [row selection](/docs/react/row-selection#payload-shape) for `RowSelectionChangeEvent`, [column selection](/docs/react/column-selection#payload-shapes) for `ColumnSelectEvent`/`ColumnsSelectEvent`/`ColumnSelectionChangeEvent`, [cell selection](/docs/react/cell-selection#payload-shapes) for `CellSelectEvent`/`CellSelectionChangeEvent`, and [row grouping](/docs/react/row-grouping) for `GroupByEvent`/`GroupExpansionEvent`.
