DataGrid implements the [WAI-ARIA grid pattern](https://www.w3.org/WAI/ARIA/apg/patterns/grid/): `role="grid"`, a single roving tab stop, and a live region for changes no visual cue alone would reach a screen reader with. A grid with an active `groupBy` switches to `role="treegrid"` — the WAI-ARIA pattern for expandable, collapsible rows — instead; an ungrouped grid is unaffected either way.

## Keyboard navigation

One cell holds the grid's tab stop at a time — <Kbd>Tab</Kbd> reaches the grid once, and the arrow keys move within it from there.

| Key                                                                                      | Moves to                                          |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------- |
| <Kbd>ArrowUp</Kbd> / <Kbd>ArrowDown</Kbd> / <Kbd>ArrowLeft</Kbd> / <Kbd>ArrowRight</Kbd> | The adjacent cell in that direction.              |
| <Kbd>Home</Kbd> / <Kbd>End</Kbd>                                                         | The first / last cell of the current row.         |
| <Kbd>Ctrl</Kbd>+<Kbd>Home</Kbd> / <Kbd>Ctrl</Kbd>+<Kbd>End</Kbd>                         | The first / last cell of the whole grid.          |
| <Kbd>PageUp</Kbd> / <Kbd>PageDown</Kbd>                                                  | Up or down by however many rows fit the viewport. |

On a focused header, <Kbd>Alt</Kbd>+<Kbd>ArrowLeft</Kbd> / <Kbd>Alt</Kbd>+<Kbd>ArrowRight</Kbd> and <Kbd>Ctrl</Kbd>+<Kbd>ArrowLeft</Kbd> / <Kbd>Ctrl</Kbd>+<Kbd>ArrowRight</Kbd> resize and reorder its column rather than move focus — see [column resizing](/docs/react/column-resizing) and [column reordering](/docs/react/column-reordering) for what they do there. <Kbd>Alt</Kbd>+<Kbd>ArrowDown</Kbd> is likewise reserved on a groupable header, for adding or removing it from the group-by stack — see [row grouping](/docs/react/row-grouping) — and <Kbd>Alt</Kbd>+<Kbd>Shift</Kbd>+<Kbd>ArrowDown</Kbd> on a header with a [filter menu](/docs/react/column-filter-menu), for opening it.

With [`contextMenu`](/docs/react/context-menu) on, <Kbd>Shift</Kbd>+<Kbd>F10</Kbd> or the <Kbd>ContextMenu</Kbd> key on a focused header, cell or group row opens its menu, the keyboard's way to a right-click. The menu follows the [WAI-ARIA menu pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/): the arrow keys, <Kbd>Home</Kbd> and <Kbd>End</Kbd> move between its items, typing a letter jumps to an item starting with it, <Kbd>Enter</Kbd>/<Kbd>Space</Kbd> runs one, and <Kbd>Escape</Kbd> or <Kbd>Tab</Kbd> closes it — focus goes back to where it was opened either way. A disabled item still takes focus, so it can be found.

Pressing <Kbd>Ctrl</Kbd>+<Kbd>C</Kbd> (<Kbd>Cmd</Kbd>+<Kbd>C</Kbd> on a Mac) anywhere in the grid copies the selection to the clipboard, or the focused cell when nothing is selected — see [clipboard](/docs/react/clipboard). It is left to the browser in a text field inside a cell, or while text is highlighted on the page, so copying highlighted text works as it does anywhere else.

The [toolbar](/docs/react/toolbar) follows the [WAI-ARIA toolbar pattern](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/): it is one tab stop of its own, before the grid's, and <Kbd>ArrowLeft</Kbd>/<Kbd>ArrowRight</Kbd> move between its controls, wrapping round, with <Kbd>Home</Kbd>/<Kbd>End</Kbd> to the first and last. The search box keeps the keys that move its caret, and the arrows lead out of it at either end of its text. A dropdown — or "More" — follows the [WAI-ARIA menu button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/): it opens its menu on its first item on <Kbd>Enter</Kbd>, <Kbd>Space</Kbd> or <Kbd>ArrowDown</Kbd>, and on its last on <Kbd>ArrowUp</Kbd>, and the menu works as the context menu's does. A disabled button still takes focus.

The [column chooser](/docs/react/column-chooser) is a dialog (`role="dialog"`, named "Columns") of native controls: focus starts in its search box, <Kbd>Tab</Kbd> moves through "Show all" and a checkbox per column, <Kbd>Space</Kbd> toggles one, and <Kbd>Escape</Kbd> closes it, giving focus back to where it was opened from. "Show all" is a tri-state checkbox, mixed while only some of the columns its search lists show.

A column's [filter menu](/docs/react/column-filter-menu) is a dialog too (`role="dialog"`, named after its column, "Name filter"), opened below its header. It holds a draft, so it keeps focus: <Kbd>Tab</Kbd> and <Kbd>Shift</Kbd>+<Kbd>Tab</Kbd> move through its controls and wrap round inside it. Focus starts on the first condition's value box. <Kbd>Enter</Kbd> in a box, a picker or a radio button applies it, as OK does, and <Kbd>Escape</Kbd> closes it without applying, giving focus back to the header. Each condition is a group ("Condition 1") of native controls, and And/Or a radio group; a value that doesn't read keeps the menu open, its box `aria-invalid` and described by the message saying so ("Enter a number"), and takes focus.

Its [excel editor](/docs/react/column-filter-menu#the-excel-editor) starts on a search box, over a native tri-state "Select all" checkbox, mixed while only some of the values its search shows are checked. The values are one `listbox` (`aria-multiselectable`, named "Values") and one stop for <Kbd>Tab</Kbd>: <Kbd>ArrowDown</Kbd>/<Kbd>ArrowUp</Kbd>, <Kbd>Home</Kbd>/<Kbd>End</Kbd> and <Kbd>PageDown</Kbd>/<Kbd>PageUp</Kbd> move among them, <Kbd>Space</Kbd> checks or unchecks one, and <Kbd>Enter</Kbd> applies. Each value is an `option` whose `aria-checked` says whether the filter keeps it; only the values near the list's scroll position are drawn, so each carries `aria-posinset` and `aria-setsize` for its place in the whole list.

Above the search box, "Text filters" — "Number filters", "Date filters" — is a menu button (`aria-haspopup="menu"`, `aria-expanded`), following the menu button pattern as the toolbar's dropdowns do: its menu of the column's conditions sits above the filter menu, so <Kbd>Escape</Kbd> or <Kbd>Tab</Kbd> closes that menu alone, giving focus back to the button. While the column is filtered by conditions, the menu's items are `menuitemcheckbox`es, the operators in use checked. Choosing one shows the conditions in the checklist's place, focus on the first one's value box, and "Back to values" brings the checklist back, focus on the button.

A group header renders as one cell spanning every column, so it holds the tab stop as a single unit rather than N per-column cells: <Kbd>ArrowLeft</Kbd>/<Kbd>ArrowRight</Kbd> are a no-op on it, and <Kbd>Space</Kbd>/<Kbd>Enter</Kbd> expand or collapse it in place of selecting anything.

Under `groupAggregateDisplay: "row"` (see [aggregate functions](/docs/react/aggregate-functions)), a group's own summary row is presentational rather than an addressable stop: <Kbd>ArrowUp</Kbd>/<Kbd>ArrowDown</Kbd>/<Kbd>PageUp</Kbd>/<Kbd>PageDown</Kbd>/<Kbd>Ctrl</Kbd>+<Kbd>End</Kbd> step straight over it, landing on the nearest row that isn't one. It still occupies a real position for `aria-rowindex`/`aria-rowcount` — see below — only the tab stop skips it.

The group-by bar sits outside the grid's own table and its single-roving-tab-stop model entirely — there's no shared position for a chip to keep in sync the way a cell has, so each chip (and its own remove button) is simply, always its own tab stop, in plain DOM order. Drag a chip to reorder the stack, or focus one and press <Kbd>Ctrl</Kbd>+<Kbd>ArrowLeft</Kbd> / <Kbd>Ctrl</Kbd>+<Kbd>ArrowRight</Kbd> — the same modifier and semantics a column header's own reorder shortcut uses. A groupable header whose column sets `groupByDraggable` can also be dragged straight into the bar, landing at whichever position among the existing chips it's released.

## ARIA attributes

| Attribute                        | Where                         | Description                                                                                                                                                                                                                                                         |
| -------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aria-rowcount`                  | The grid                      | Total rows, header included — one more than the row count of `dataSource` as filtered, sorted, and grouped, plus one per group's own summary row under `groupAggregateDisplay: "row"`. The full dataset count, not just the current page's, once `paginated` is on. |
| `aria-colcount`                  | The grid                      | Total columns as currently sized and ordered.                                                                                                                                                                                                                       |
| `aria-rowindex`                  | Every row                     | 1-based; the header is row 1, so the first body row is row 2. Built from each row's absolute dataset position, not its page-relative one — see [pagination](/docs/react/pagination#rowindex-vs-the-rows-dataset-position).                                          |
| `aria-colindex`                  | Every header and body cell    | 1-based, following the current column order.                                                                                                                                                                                                                        |
| `aria-multiselectable`           | The grid                      | Set to `true` when `selectable.rows` or `selectable.columns` is `"multiple"`. Omitted otherwise.                                                                                                                                                                    |
| `aria-selected`                  | Row, column header, and cell  | Reflects whether that row/column/cell is selected — but only when that dimension's selection is enabled at all. Omitted, not `false`, when it isn't: a display-only grid never claims to have an unselected anything.                                               |
| `aria-sort`                      | Column headers                | `"ascending"` or `"descending"` once a sortable column has an active sort direction. Omitted — not `"none"` — for an unsorted or unsortable column.                                                                                                                 |
| `aria-description`               | Column headers                | "Filtered" while a column with a filter menu is filtered — the `columnFiltered` message.                                                                                                                                                                            |
| `aria-keyshortcuts`              | Column headers and body cells | Lists whichever shortcuts that column or cell actually responds to (below), so they're discoverable rather than assumed.                                                                                                                                            |
| `aria-expanded`                  | Group header rows             | Whether that group is currently expanded or collapsed.                                                                                                                                                                                                              |
| `aria-level`                     | Group header rows             | 1-based nesting depth — 1 for a top-level group, 2 for one nested inside it, and so on.                                                                                                                                                                             |
| `aria-label`                     | The context menu              | Names the menu: a header's after its column, "Name column menu"; a cell's "Row menu"; a group row's "Group menu"; empty body space's "Grid menu" — the `headerMenuLabel`, `cellMenuLabel`, `groupMenuLabel` and `bodyMenuLabel` messages.                           |
| `aria-disabled` / `aria-checked` | Context menu items            | A disabled item, which stays focusable; and a checkable item's state — "Sort ascending" is checked while the column sorts ascending.                                                                                                                                |
| `aria-label`                     | The filter menu               | Names the dialog after its column, "Name filter" — the `filterMenuLabel` message.                                                                                                                                                                                   |
| `aria-pressed`                   | Filter menu sort entries      | "Sort ascending" or "Sort descending", pressed while the column sorts that way.                                                                                                                                                                                     |
| `aria-invalid`                   | Filter menu value boxes       | Set on a box whose value is missing or doesn't read once OK is pressed, with `aria-describedby` pointing at the message saying so — the `filterValueInvalid` message.                                                                                               |
| `aria-checked`                   | Filter checklist values       | Whether the filter keeps the value, on each `role="option"` of the excel editor's `listbox`, which is `aria-multiselectable`.                                                                                                                                       |
| `aria-posinset` / `aria-setsize` | Filter checklist values       | The value's 1-based place among, and the count of, the values the list holds — only those near its scroll position are drawn.                                                                                                                                       |
| `aria-expanded`                  | Filter menu "Text filters"    | Whether the excel editor's menu of conditions is open, on the button opening it, which carries `aria-haspopup="menu"`.                                                                                                                                              |
| `aria-label` / `aria-controls`   | The toolbar                   | Names the toolbar — "Grid toolbar", the `toolbarLabel` message, or its `label` — and points it at the grid it acts on.                                                                                                                                              |
| `aria-disabled` / `aria-pressed` | Toolbar buttons               | A disabled button, which stays focusable; and a toggle's state. A dropdown carries `aria-haspopup="menu"` and `aria-expanded`.                                                                                                                                      |
| `aria-posinset` / `aria-setsize` | Group header rows             | That group's 1-based position among, and count of, the group headers sharing its level and immediate parent.                                                                                                                                                        |

A column header's `aria-keyshortcuts` names whichever of these apply, space-separated:

- `Control+ArrowLeft Control+ArrowRight` when the column is [reorderable](/docs/react/column-reordering).
- `Alt+ArrowLeft Alt+ArrowRight Alt+Enter` when the column is [resizable](/docs/react/column-resizing) — the first two nudge its width, the last sizes it to its content.
- `Alt+ArrowUp` when the column is [sortable](/docs/react/column-sorting).
- `Alt+ArrowDown` when the column is [groupable](/docs/react/row-grouping).
- `Alt+Shift+ArrowDown` when the column has a [filter menu](/docs/react/column-filter-menu).
- `Shift+F10` while a header opens the grid's [context menu](/docs/react/context-menu).

A body cell's `aria-keyshortcuts` is `Space Enter` when cell selection is on — see [cell selection](/docs/react/cell-selection), and lists `Shift+F10` too while a cell opens the grid's context menu. A group row's is `Space Enter`, and `Space Enter Shift+F10` while a group row opens one.

## Live announcements

A `role="status" aria-live="polite"` region, outside the table itself, reports changes that have no visual cue a screen reader could otherwise pick up on:

- **Column resize** — only on release (`phase: "end"`), not on every frame of the drag: a live region updated on each pointermove would say nothing an assistive technology could keep up with. Announces the column's name and its new width in pixels. Autofitting one column announces the same way.
- **Autofit** — fitting more than one column at once, as "Autofit all columns" or the ref's `autoFitColumns` does, announces how many in place of each one's width ("3 columns autofitted").
- **Column reorder** — on drop. Announces the column's name and its new position, as "column _n_ of _total_".
- **Sort change** — a toggle, a stack, or a clear back to unsorted are each phrased differently: a plain toggle announces the column and its new direction; adding or updating a column in a multi-column sort also announces its priority ("key _n_ of _total_"); clearing a column's sort announces that its sort was cleared.
- **Row and column selection changes** — only when more than one row or column changes in the same interaction (a range, a select-all, <Kbd>Ctrl</Kbd>+<Kbd>A</Kbd>). A single selection is already carried by that row's or column's own `aria-selected`, so announcing it too would talk over what a screen reader just read. Announces the resulting total, e.g. "3 rows selected".
- **Cell selection** — every time a selection lands on a cell. Unlike row and column selection, a cell selection is always exactly one cell, so there's no multi-item threshold to cross — the announcement fires on every commit instead, naming the column and row the selected cell is in.
- **Group-by change** — adding, removing, or repositioning a level (via the header toggle, a header dropped on the bar, a dragged chip, or a chip's own <Kbd>Ctrl</Kbd>+<Kbd>ArrowLeft</Kbd> / <Kbd>Ctrl</Kbd>+<Kbd>ArrowRight</Kbd>) announces the column and, once two or more levels are stacked, its position ("level _n_ of _total_"); removing any column from the grouping announces that its grouping was removed ("Region, grouping removed"). Every path funnels through the same announcement, so a drag and a click read identically.
- **Column visibility** — hiding or showing one column, from the context menu, the column chooser or the ref's `hideColumns`/`showColumns`, announces the column and which ("Name, column hidden"); hiding or showing several at once, as the chooser's "Show all" does, announces how many ("3 columns hidden").
- **Copy** — once a copy is on the clipboard, announces what it holds ("3 rows copied", "1 cell copied"), as nothing on screen shows it; a copy the browser refuses announces "Copy failed".
- **Search** — once a search typed into the toolbar's box applies, announces how many rows it found ("3 rows found").
- **Filter menu** — once a column's [filter menu](/docs/react/column-filter-menu) applies and the grid has drawn the rows its filter keeps, announces how many of all the rows they are ("2 of 3 rows").
- **Group expand/collapse** — a single group toggle announces "Group expanded"/"Group collapsed"; `expandAllGroups()`/`collapseAllGroups()` announce the whole-tree result instead ("All groups expanded"/"All groups collapsed").
- **Page change** — moving to another page or changing the page size announces where the grid is now, as the `pageStatus` message has it ("Page 2 of 5"). The silent reset to the first page a filter, sort or regroup causes is not announced on its own.

Each announcement's wording is a `messages` key, so it can be translated — see [localization](/docs/react/localization).
